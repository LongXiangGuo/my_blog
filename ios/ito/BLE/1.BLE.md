# 蓝牙完整技术体系梳理

主要内容经典蓝牙BR/EDR vs BLE低功耗蓝牙、架构、协议栈、全流程机制

## 一、蓝牙两大技术分支：BR/EDR经典蓝牙 & BLE低功耗蓝牙
### 1 基础定义与核心定位

# 经典蓝牙 BR/EDR vs 低功耗蓝牙 BLE 对比表

| 对比维度     | 经典蓝牙 BR/EDR（v1.0~v3.0+HS）                  | 低功耗蓝牙 B（蓝牙4.0~v6.0）                             |
| ------------ | ------------------------------------------------ | -------------------------------------------------------- |
| 开发定位     | 高速音频、大文件、连续数据流（耳机、车机、串口） | 超低功耗物联网设备（手环、传感器、数字钥匙、定位）       |
| 发射功耗     | 高，持续射频发射，待机耗电高                     | 99%时间处于休眠，仅广播/连接瞬间发射，纽扣电池可续航数月 |
| 底层架构     | 独立老旧协议栈，与BLE底层不互通                  | 全新独立架构，不兼容BR基带，仅上层密钥可互通             |
| 理论传输速率 | BR：1Mbps / EDR：3Mbps / AMP：24Mbps             | LE 1M/2M/编码PHY，峰值2Mbps                              |
| 典型上层协议 | A2DP、HFP、SPP、RFCOMM                           | GATT、ATT、LE Audio、信道测距、PAwR周期性广播            |
| iOS系统支持  | 仅MFi认证外设可用，CoreBluetooth不开放BR接口     | iOS全原生支持，CoreBluetooth专属开发框架                 |
| 最新核心特性 | AMP Wi-Fi高速借道（v3.0，v5.3规范已废弃）        | v6.0厘米级信道测距、LE Audio、PAwR双向广播               |

### 2 版本核心迭代重点
1. BR时代（v1.2~2.1+EDR）：EDR提速、SSP安全简易配对；
2. v3.0+HS：AMP Wi-Fi借道传输，后被SIG废弃；
3. v4.0分水岭：新增BLE完整新链路层、ATT/GATT协议，IoT时代开启；
4. v5.0~5.4：长距离编码PHY、大广播包、PAwR传感器双向广播；
5. v5.2：LE Audio LC3音频、CIS单播/BIS广播立体声；
6. v6.0（现行最新规范）：Channel Sounding信道测距、硬件级广播过滤、帧间隔动态调节、加密广播。

### 3 SIG规范文档区分
- Core v6.0 Vol2：BR/EDR控制器（传统蓝牙基带、LMP协议）
- Core v6.0 Vol6：BLE链路层、PHY、DTM测试、信道测距
- 配套Profile规范：A2DP/HFP属于BR；Battery/心率/测距服务属于BLE

## 二、蓝牙完整分层架构（Host主机 + Controller控制器 + HCI接口）
整套蓝牙软硬件分层是Core规范核心框架，分为三层，硬件/软件边界清晰
### 1 三层整体架构
1. **Controller 控制器（蓝牙芯片固件，硬件侧）**
纯硬件/芯片固件层，负责射频、基带、底层时序，微秒级实时无线处理，分两套实现：
- BR控制器：Vol2，LM链路管理器、Baseband基带；
- BLE控制器：Vol6，LL链路层、BLE PHY、CTE测距；
核心职责：2.4G射频收发、跳频、数据包编解码、CRC校验、射频时序、DTM硬件测试。
2. **HCI 主机控制器接口（中间标准通道，Vol4完整规范）**
标准化通信协议，隔离主机与芯片，支持UART/USB/SD/三线串口四种物理传输；
iOS抓包（PacketLogger）、外设调试、产线DTM测试全部基于HCI命令/事件；
HCI四大数据包类型：命令、事件、ACL普通数据、ISO音频数据。
3. **Host 主机（操作系统软件，iOS/Android内核协议栈）**
运行在手机CPU，无射频硬件，负责业务逻辑、安全算法、上层协议；
BR主机协议：L2CAP、SDP、RFCOMM、A2DP/HFP；
BLE主机协议：L2CAP、ATT、GATT、SMP安全管理器。

### 2 角色补充（链路层主从 vs GATT服务端客户端）
#### （1）链路层角色（Controller层定义）
- Central 主机：掌握连接时序、连接间隔、跳频规则（手机、平板）；
- Peripheral 从机：被动同步主机时序（手环、传感器，俗称BLE从机）；
99%场景一一对应：Central=GATT客户端，Peripheral=GATT服务器。
#### （2）GATT业务角色（BLE Host层）
- GATT Server（从机数据库）：外设本地存储所有传感器/控制数据，以属性表存储，Handle为行索引；
- GATT Client（客户端）：iOS手机，主动读写、订阅外设数据。

## 三、完整蓝牙协议栈（分BR/EDR、BLE两套独立栈）
### 1 经典蓝牙 BR/EDR 协议栈（自上而下）
```
【应用层Profile】A2DP / HFP / SPP / OBEX
        ↓
【RFCOMM】串口仿真协议
        ↓
【SDP 服务发现】查询外设支持的服务
        ↓
【L2CAP】逻辑链路适配层，分段/流控
        ↓
【HCI 主机控制器接口】
        ↓
【LMP 链路管理协议】BR底层协商、配对加密
        ↓
【Baseband 基带】数据包组装、FEC、CRC
        ↓
【BR射频PHY 2.4GHz】
```
### 2 BLE低功耗蓝牙协议栈（Core v6.0 Vol3/6标准分层）
```
【应用层GATT Profiles】电量、心率、LE Audio、测距服务
        ↓
【ATT 属性协议】GATT底层数据读写载体
        ↓
【SMP 安全管理器】BLE配对、密钥、OOB/NFC配对
        ↓
【L2CAP BLE专用】信用流控、CoC面向连接通道
        ↓
【HCI 主机控制器接口】
        ↓
【LL BLE链路层】广播、连接、PHY切换、CTE测距
        ↓
【BLE PHY 1M/2M/编码射频】
```
### 3 各层核心协议详解
#### 3.1 控制器底层协议（LL / LMP + 基带/射频）
1. BLE LL链路层（Vol6 Part B）
BLE核心底层，定义广播包、连接包、CTE测距包；管理待机/广播/扫描/发起/连接五大状态；实现跳频、数据白化、FEC纠错、CRC4校验；Handle索引对应底层数据包字段。
2. BR LMP链路管理协议（Vol2 Part C）
传统蓝牙底层协商功率、连接参数、配对加密；
3. 射频&基带：调制、发射功率、灵敏度、信道排布，DTM测试模式（Vol6 F）用于产线射频校准。

#### 3.2 HCI 主机控制器接口（Vol4）
主机与芯片唯一标准通信通道，iOS调试核心；
命令：扫描、建连、PHY切换、测距、音频通道创建；
事件：广播上报、连接完成、断连报错、RSSI信号、配对弹窗触发；
错误码全集：断连、认证失败、资源耗尽等故障对应iOS CBError。

#### 3.3 L2CAP 逻辑链路控制（Vol3 A）
两套蓝牙共用上层适配层，但实现完全不同：
- BR-L2CAP：面向连接/无连接通道，适配RFCOMM音频；
- BLE-L2CAP：Credit信用流控、CoC面向连接高速通道，支持64KB超大MTU，适合OTA、实时传感器；
核心优势：独立数据管道，不与GATT队列阻塞，iOS高速传输首选。

#### 3.4 BR专属上层协议
1. SDP：服务发现，查询外设支持A2DP/HFP；
2. RFCOMM：虚拟串口，SPP底层载体；
3. A2DP/HFP：音频通话Profile。

#### 3.5 BLE专属上层协议（iOS开发核心）
1. ATT属性协议：BLE最小数据交互单元，定义Handle（属性索引）、读写/通知指令；
2. GATT通用属性规范：数据分层架构（服务→特征→描述符），定义四种交互：读/写/Notify通知/Indicate指示；
3. SMP安全管理器（Vol3 H）：BLE配对、四种配对方式（数字比对/密钥/OOB/无交互）、密钥体系LTK/IRK/CSRK、随机私有地址隐私机制；

## 四、BLE GATT数据库 & Handle索引完整原理（iOS开发高频）
### 1 GATT Server（BLE从机）本质
外设内置一张线性属性数据库，每条属性分配唯一**16位Handle（句柄/索引，0x0001~0xFFFF）**，是数据库主键。
### 2 三层数据结构
1. Service服务：数据分类，占用一段连续Handle区间（起始Handle+结束Handle）；
2. Characteristic特征：真实数据存储单元，带UUID、读写权限、通知开关；
3. Descriptor描述符：特征附属配置（CCCD 0x2902开启通知）。
### 3 UUID vs Handle 区分
- UUID：全球统一标识（如0x2A19=电量），代表数据含义；
- Handle：单台外设本地索引，仅当前设备有效，抓包、iOS读写底层唯一寻址标识；
类比：UUID=商品名称，Handle=外设本地货架编号。
### 4 为什么不用GATT传高速指令
GATT单队列阻塞、MTU偏小、服务发现流程繁琐；L2CAP-CoC独立流通道无排队，大MTU、省去服务扫描，车载/OTA实时通信优先选用。

## 五、蓝牙全标准工作流程（广播→扫描→配对→认证→加密→数据订阅传输）
### 流程1：广播与扫描（BLE设备发现）
1. 从机Peripheral周期性发送广播数据包（Adv），可携带设备名称、服务UUID、自定义数据；
2. 主机Central（iOS）开启扫描，分两种模式：
   - 被动扫描：仅接收广播，不回复，低功耗；
   - 主动扫描：发送SCAN_REQ请求，获取完整扫描响应数据；
3. v6.0新增硬件广播过滤、PAwR带响应周期性广播，外设无需建连即可上传数据；
4. 隐私机制：iOS自动轮换RPA可解析随机MAC，外设需IRK密钥解析真实地址。

### 流程2：连接建立
1. iOS扫描到目标外设，发送连接请求LL控制包；
2. 链路层协商连接间隔、从机延迟、信道映射、PHY速率；
3. 连接完成HCI_CONNECTION_COMPLETE事件上报iOS系统；
4. 主机自动发起GATT服务发现，遍历所有Handle区间，缓存服务/特征。

### 流程3 配对Pairing & 认证Authentication（SMP协议，Vol3 H）
#### 1 四种标准配对模式（SMP定义）
1. 数字比对Numeric Comparison：两端显示6位数字确认（AirPods、手环通用，iOS弹窗）；
2. 密钥输入Passkey：手机弹窗输入6位PIN；
3. OOB带外配对：NFC/二维码交换公钥、随机数；
   - 规范层面标准支持；
   - iOS限制：第三方外设无法通过NFC自动跳过配对弹窗，仅苹果自有W1/H1设备私有实现；
4. Just Works无交互配对，无弹窗自动绑定。
#### 2 配对完整四阶段
1. 能力交换：两端IO能力、安全模式、是否支持安全连接SC；
2. 公钥交换：v4.2起强制P-256椭圆曲线（iOS13仅支持SC安全连接模式，废弃老式加密）；
3. 校验值确认（数字比对弹窗触发点）；
4. 密钥分发：LTK长期密钥、IRK身份解析密钥、CSRK签名密钥下发存储。

### 流程4 链路加密
1. 配对完成生成LTK长期密钥；
2. iOS主机下发加密HCI指令，链路层基于AES-CCM加密所有空口数据包；
3. 加密失败MIC校验错误（HCI 0x3D）对应iOS断连报错；
4 广播加密（v6.0新特性）：广播包可加密，需密钥解析广播数据。

### 流程5 数据交互：GATT / L2CAP双通道两种方式
#### 方式1 GATT读写/订阅（常规传感器、手环）
1. 读Read：iOS下发Handle读取特征数值；
2. 写Write/无响应写：下发控制指令；
3. Notify通知：外设数据变更主动推送（无需主机应答，实时心率/电量）；
4. Indicate指示：推送+主机必须应答，高安全数据使用；
#### 方式2 L2CAP CoC高速流通道（OTA、车载实时指令）
连接后通过固定PSM端口建立独立数据流，不分片、无队列阻塞，低延迟大吞吐量。

### 流程6 断连与重连
1. 主动断连：App调用断开，或系统后台回收蓝牙；
2. 被动断连：信号丢失、超时、MIC加密错误、外设休眠；
3. 绑定设备存储IRK/LTK，iOS后台可自动重连无需重新配对。

## 六、v6.0核心新增能力（SIG官网规范新增条目）
1. Channel Sounding信道测距：厘米级定位，基于相位+RTT往返时间，防范中继攻击，数字钥匙必备；
2. 基于判定的硬件广播过滤，降低iOS扫描功耗；
3. 广播设备持续监测，无需建连监控外设；
4. ISOAL音频层大幅优化CIS/BIS，多设备同步音频；
5. PAwR周期性广播增强，海量传感器双向低功耗通信；
6. 动态帧间隔调节，平衡延迟与功耗。

## 七、BR/EDR 特有AMP机制补充（v3.0，现已废弃）
AMP=替代MAC/PHY，蓝牙建立控制连接，大数据传输时借用Wi-Fi 802.11物理层，传输完成关闭Wi-Fi射频；
硬件要求蓝牙+Wi-Fi Combo芯片，因兼容性差，蓝牙v5.3规范彻底移除该功能，苹果AirDrop、安卓快传均为系统私有实现，不遵循AMP标准。
