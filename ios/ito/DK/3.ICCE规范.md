# ICCE规范全面解析


## 一、简介

### 1.1 联盟背景

**ICCE**（Intelligent Car Connectivity Industry Ecosystem Alliance，智慧车联产业生态联盟）成立于2019年，是中国汽车工业协会下属协会，也是国内首个移动智能终端和汽车行业跨界产业联盟。联盟由中国汽车工业协会牵头成立，核心成员包括华为、比亚迪、上汽等头部企业，覆盖整车、芯片、终端、检测等全链条。截至目前，联盟成员已达80余家，包括全球重要车企及汽车产业链端到端主流厂家。

ICCE联盟的使命是：**汇聚产业力量，共建移动终端和汽车互联与协作生态，促进相关产业成员之间的交流和深度合作，减少产业碎片化，面向商业成功，有效推进产业健康有序发展**。

### 1.2 规范定位

ICCE规范是国内首个**跨移动终端、跨汽车的统一互联标准**，旨在为移动终端和汽车的共同演进发展打造“高速公路”。该规范由联盟手机-汽车互联工作组全体成员的共识和成果凝结而成，完成了基本架构和主要协议的定义，为后续系列标准的加速制定奠定了重要基础。

### 1.3 技术标准体系

ICCE联盟已构建了两大技术标准体系：

| 标准体系                   | 主要内容                                                                           |
| -------------------------- | ---------------------------------------------------------------------------------- |
| **数字车钥匙系统**         | 总体要求、蓝牙系统规范、NFC系统要求、UWB分册、星闪系统要求等                       |
| **移动终端与车载设备互联** | 系统架构、发现连接、应用服务协议、融合互联技术要求、体验测评规范、性能符合性测试等 |

截至目前，已有12家整车企业、共20多款车型商用或即将商用ICCE数字车钥匙，基于ICCE开放手机-车机互联标准的车型已经达到350款以上。2022年11月，国际电信联盟（ITU-T）正式采纳ICCE手机-汽车互联标准内容。


## 二、架构设计

### 2.1 整体架构概述

ICCE互联架构的核心是定义移动终端（手机）与车载设备（车机）之间的标准化通信框架。根据《移动终端与车载设备互联技术规范 第1部分：系统架构》，架构主要包含以下维度：

- **协议拓扑（Protocol Topology）** ：定义通信协议的整体结构关系
- **硬件资源拓扑（Hardware Resource Topology）** ：定义双方硬件能力的映射与共享方式
- **业务连接通道（Service Connection Channel）** ：定义不同业务类型的传输通道
- **协议堆栈（Protocol Stack）** ：定义从物理层到应用层的完整协议层次

### 2.2 互联融合框架

随着技术演进，ICCE提出了**融合互联（Fusion Connectivity）** 架构，将互联从简单的“投屏”升级为深度“融合”。融合规范划分了四类融合场景：

1. **应用融合（Application Fusion）** ：将手机上的应用与车机应用融合展示，实现应用生态共享
2. **数据融合（Data Fusion）** ：将手机、汽车、IoT设备的用户数据融合
3. **硬件融合（Hardware Fusion）** ：打通手机算力和车机硬件，开放IoT设备控制能力
4. **交互融合（Interaction Fusion）** ：手机交互体验无缝融入原生车机系统（语音助手、UI布局、使用流畅性等）

融合互联的协议框架规定了**融合元数据（Fusion Metadata）** 的交互流程和格式。

### 2.3 协议层次结构

从协议堆栈的角度，ICCE互联架构可分为：

| 层次                                                | 功能                                                       |
| --------------------------------------------------- | ---------------------------------------------------------- |
| **应用服务层（Application Service Layer）**         | 语音/导航/电话/媒体服务调用、车辆信息获取与控制            |
| **分布式协同层（Distributed Collaboration Layer）** | 应用状态协同、数据协同（导航/媒体/电话数据）               |
| **连接通道层（Connection Channel Layer）**          | 应用通道、共享上网通道管理                                 |
| **发现连接层（Discovery & Connection Layer）**      | 设备发现、连接建立与维护                                   |
| **物理传输层（Physical Transport Layer）**          | 有线连接（USB）、无线连接（蓝牙、Wi-Fi、NFC、UWB、星闪等） |


## 三、实现原理

### 3.1 核心设计思想

ICCE规范的核心设计思想是**标准化、模块化、可扩展**：

- **标准化（Standardization）** ：通过统一协议接口，消除各厂商私有协议带来的碎片化
- **模块化（Modularization）** ：各功能层独立定义，可单独实现和升级
- **可扩展（Extensibility）** ：兼容多种物理传输技术（蓝牙、NFC、UWB、星闪等）

### 3.2 关键技术原理

#### （1）设备发现与连接（Device Discovery & Connection）

ICCE规范定义了标准化的设备发现和连接流程，支持有线和无线两种方式：
- **有线连接**：通过USB物理连接，实现高带宽、低延迟的数据传输
- **无线连接**：通过蓝牙进行设备发现和配对，通过Wi-Fi进行高速数据传输

#### （2）应用服务协议（Application Service Protocol）

《应用服务协议》定义了应用层接口协议框架，包括：
- **服务调用接口**：语音助手唤醒、导航/电话/媒体服务调用
- **Sensor状态事件接口**：驾驶模式、白天/黑夜模式、油电状态
- **车辆设备信息接口**：品牌信息、驾驶位置、交互能力、视频投屏
- **车辆设备控制接口**：空调控制、车窗控制、音量控制
- **分布式协同接口**：导航焦点协同、电话状态协同、语音助手状态协同
- **分布式数据协同接口**：导航数据、媒体数据、电话数据协同

#### （3）融合互联技术（Fusion Connectivity Technology）

融合互联的实现原理是：**移动终端将应用信息、消息通知等通过元数据（Metadata）的方式发送至汽车，在车机屏幕上以融合桌面的形式展示来自手机的应用和信息**。这种方式不需要完整的应用迁移，而是通过元数据交换实现轻量级、高效的互联体验。

#### （4）数字车钥匙安全机制（Digital Car Key Security）

ICCE数字车钥匙标准通过 **“芯-端-云”一体化安全防护**（Chip-Device-Cloud Integrated Security），实现钥匙的安全传输、安全存储和安全使用。安全机制包括：
- **SE（Secure Element，安全元件）** ：硬件级密钥存储
- **TEE（Trusted Execution Environment，可信执行环境）** ：隔离的安全运行环境
- **端到端加密（End-to-End Encryption）** ：钥匙数据的全程加密传输

### 4.2 数字车钥匙完整业务流程

ICCE数字车钥匙的完整业务流程包括：

1. **开通（Activation）** ：用户在移动设备上申请并下载数字钥匙
2. **使用（Usage）** ：通过NFC/蓝牙/UWB/星闪实现车辆开门、启动等功能
3. **分享（Sharing）** ：车主将数字钥匙分享给其他用户
4. **更新（Update）** ：钥匙信息的远程更新
5. **冻结（Freeze）** ：临时禁用钥匙权限
6. **恢复（Recovery）** ：恢复被冻结的钥匙
7. **撤销（Revocation）** ：永久撤销钥匙权限

### 4.3 星闪数字车钥匙流程

ICCE星闪数字车钥匙标准融合了ICCE数字车钥匙基础框架和星闪技术，制定了专门流程：

```
星闪广播接入 → 配对连接 → 测距定位 → 车钥匙认证 → 无感进入
```

该流程充分发挥了星闪SLE（SparkLink Low Energy）技术低功耗、低时延、抗干扰能力强、定位精度高、安全性高等优势。

## 六、使用场景和用途

### 6.1 主要使用场景

#### （1）手机-汽车互联场景

这是ICCE规范最核心的应用场景，具体包括：

- **导航流转**：手机上的导航应用无缝流转到车机大屏显示和操作
- **音频播放**：手机音乐/播客通过车机音响系统播放
- **电话服务**：车载环境下的免提通话
- **语音交互**：通过车机语音助手调用手机应用和服务
- **应用生态共享**：手机百万级App生态与汽车无缝协作
- **硬件互助**：共享手机AI算力和5G上网能力，共享汽车GPS信号补充给手机

#### （2）数字车钥匙场景

- **无感进入**：用户携带手机靠近车辆，自动解锁车门
- **无感启动**：手机在车内即可启动车辆
- **钥匙分享**：远程将数字钥匙分享给家人或朋友
- **手表/手环车控**：通过手表语音进行车控操作

#### （3）智能座舱融合场景

- **身份识别**：手机识别用户身份，自动调整座椅、后视镜等设置
- **服务推荐**：基于用户习惯推荐导航路线、音乐等
- **多终端协同**：“车与人”“车与家”“车与路”等多场景深度互联

### 6.2 产业价值

ICCE规范的核心价值在于：

1. **降低行业成本**：减少定制化开发，降低互联互通成本
2. **提高开发效率**：统一标准缩短对接周期
3. **保障互联互通**：跨手机、跨汽车的兼容性保障
4. **提升用户体验**：稳定、流畅的互联体验


## 七、各平台差异

### 7.1 移动终端平台差异

ICCE作为**跨移动终端**的统一标准，理论上支持所有主流移动操作系统。但从产业实际来看，存在以下差异：

| 维度         | Android                        | iOS                         | 鸿蒙（HarmonyOS）        |
| ------------ | ------------------------------ | --------------------------- | ------------------------ |
| **支持程度** | 广泛支持，多数安卓厂商已集成   | 支持，但需遵循Apple生态限制 | 原生支持，分布式能力突出 |
| **主要厂商** | 华为、荣耀、小米、OPPO、vivo等 | iPhone                      | 华为、荣耀               |
| **实现方式** | 通过ICCE标准协议栈             | 通过ICCE标准+MFi限制        | 通过ICCE+分布式软总线    |

从公开信息来看，目前ICCE互联方案在华为、荣耀等厂商中落地较为深入。

### 7.2 车载平台差异

| 维度             | 差异点                                   |
| ---------------- | ---------------------------------------- |
| **硬件型号**     | 不同车型硬件配置差异大，影响互联性能     |
| **OS版本**       | 车机操作系统版本不统一，适配工作量大     |
| **软件协议**     | 各厂商私有协议定制多，标准化程度不一     |
| **音频处理策略** | 音频焦点、音频分流、混音、音量等策略不同 |

### 7.3 互联方案差异

行业中存在多种手机-汽车互联方案，ICCE是其中之一。根据ICCE发布的测评报告，不同互联方案的体验得分差异显著，HUAWEI HiCar获得96.63分（满分100），在测评中排名第一。这反映了不同平台/方案在实现质量上存在差异。

### 7.4 ICCE的跨平台统一价值

ICCE规范的核心目标正是**消除上述平台差异带来的碎片化问题**：

- 对**手机厂商**：只需实现一套ICCE标准协议，即可兼容所有支持ICCE的车型
- 对**整车厂**：只需集成ICCE标准，即可兼容所有支持ICCE的手机品牌
- 对**用户**：无论使用什么品牌的手机或汽车，都能获得一致的互联体验


## 八、总结

ICCE规范是中国智能终端与汽车产业跨界融合的重要成果。它通过标准化的**系统架构**、**应用服务协议**、**融合互联技术要求**和**数字车钥匙系统**，构建了一套完整的手机-汽车互联技术体系。该规范已被ITU-T国际标准采纳，在产业中得到了广泛的应用和验证，覆盖了从数字车钥匙到应用生态共享、从硬件互助到数据融合的多样化场景，为推动智慧车联产业的健康发展提供了坚实的技术基础。
