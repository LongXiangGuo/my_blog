# Core Motion 全面解析：从入门到生产实践

Core Motion 是 Apple 生态中处理设备运动数据的核心框架，自 iOS 4.0 引入以来，已发展成为覆盖 iPhone、iPad、Apple Watch、visionOS 乃至 AirPods 等音频设备的综合性运动数据访问框架。本文将从基础概念到生产级实践，全面剖析 Core Motion 的工作原理、使用方法及工程化经验。

---

## 一、Core Motion 简介

Core Motion 是一个中央框架，用于访问来自惯性传感器的运动和环境相关数据，包括加速度计、陀螺仪、磁力计、气压计，以及经过传感器融合算法处理后的设备姿态、用户加速度等。其核心价值在于：

> **Core Motion 不仅提供原始传感器数据，还通过传感器融合算法输出可直接使用的运动信息，极大降低了开发者的数据处理门槛。**

### 1.1 发展历程

- **iOS 4.0**：首次引入，提供加速度、陀螺仪和设备运动数据。
- **iPhone 5S（M7 协处理器）** ：引入专用运动协处理器，支持全天候低功耗运动数据采集。
- **iPhone 6（M8 + 气压计）** ：新增气压计，支持海拔和楼层统计。
- **watchOS 2.0**：支持扩展至 Apple Watch。
- **iOS 14**：引入 `CMHeadphoneMotionManager`，支持 AirPods Pro 头部运动追踪。
- **visionOS 1.0**：支持 Apple Vision Pro。

### 1.2 框架定位

Core Motion 位于应用层与硬件传感器层之间，职责包括：

- 采集加速度计、陀螺仪、磁力计、气压计等原始数据；
- 通过传感器融合算法（如卡尔曼滤波）处理数据；
- 以原始值或处理后值的形式向应用提供数据。

## 五、工作流程与代码实现

### 5.1 标准工作流程

1. **导入框架** `import CoreMotion`
2. **配置权限**：在 `Info.plist` 添加 `NSMotionUsageDescription`
3. **创建 CMMotionManager 实例**（单例）
4. **检查传感器可用性**
5. **配置更新频率**
6. **启动数据更新**（Push 或 Pull）
7. **处理数据**
8. **停止更新**（适时释放资源）

### 5.2 基础代码示例

```swift
import CoreMotion

class MotionManager {
    static let shared = MotionManager()
    private let manager = CMMotionManager()
    private let queue = OperationQueue()
    
    private init() {
        queue.maxConcurrentOperationCount = 1
    }
    
    func startDeviceMotion(interval: TimeInterval = 1.0/60.0) {
        guard manager.isDeviceMotionAvailable else { return }
        manager.deviceMotionUpdateInterval = interval
        manager.startDeviceMotionUpdates(using: .xArbitraryZVertical, to: queue) { 
            [weak self] motion, error in
            guard let motion = motion else { return }
            // 处理 motion.attitude, motion.userAcceleration 等
        }
    }
    
    func stop() {
        manager.stopDeviceMotionUpdates()
    }
}
```

### 5.3 计步器示例

```swift
let pedometer = CMPedometer()
pedometer.startUpdates(from: Date()) { data, error in
    let steps = data?.numberOfSteps
    let distance = data?.distance
}
```

### 5.4 耳机运动追踪

```swift
let headphoneManager = CMHeadphoneMotionManager()
headphoneManager.startDeviceMotionUpdates(to: .main) { motion, error in
    // 处理头部姿态
```

## 七、生产环境实践

### 7.1 数据采集频率策略

选择频率需在信息量与性能间平衡：

| 应用场景            | 推荐频率  |
| ------------------- | --------- |
| 游戏 / AR           | 60~100 Hz |
| 健身追踪 / 手势识别 | 10~50 Hz  |
| 步数 / 状态监测     | 1~5 Hz    |

**核心原则**：使用满足需求的最低频率，并在每次回调中避免大量计算。

### 7.2 多模态时间统一上抛

当融合多种传感器（相机、GPS、麦克风）时，必须统一时间基准。

- Core Motion 数据自带 `timestamp`，为系统启动后的相对时间。
- 转换为统一基准（如 `Date`）：
```swift
let uptime = ProcessInfo.processInfo.systemUptime
let date = Date(timeIntervalSinceNow: motion.timestamp - uptime)
```
- 上抛数据结构必须包含统一时间戳，便于后端对齐分析。

### 7.3 数据防抖与截流

- **防抖（平滑）**：信号处理层面去除噪声，`CMDeviceMotion` 已内置卡尔曼滤波。
- **截流（节流）**：应用层控制上报频率，例如每 N 条数据聚合后上报，或设置时间窗口批量发送。

### 7.4 冗余数据处理

- 高频数据对机器学习训练有价值，不必视为“冗余”。
- 可采用本地存储 + 闲时上传策略，或在线降采样、特征提取后上抛。

## 八、应用层平滑滤波完全指南（从入门到实战法则）

虽然 `CMDeviceMotion` 已内置传感器融合算法，但在极端抖动或需要流畅动画的场景下，应用层往往需要二次平滑。本章节将用**零基础也能听懂的语言**，彻底拆解 **EMA** 与 **四元数 Slerp**，并给出**绝对不搞混的硬核实战法则**。

### 8.1 问题本质：我们在对抗什么？

手机传感器数据存在两类令人头疼的“原生缺陷”：
1.  **数值抖动**：手部微颤导致加速度、转速读数高频震荡（像得了帕金森）。
2.  **旋转生硬**：受磁场干扰或姿态解算跳变，屏幕方向（如指南针）瞬间从 0° 弹到 90°，缺乏中间过渡。

EMA 专治第一种，四元数 Slerp 专治第二种。

---

### 8.2 指数移动平均（EMA）：专治“数据抖成筛子”

#### 8.2.1 核心公式（只有加减乘除）
\[
\text{今天平滑值} = \text{昨天平滑值} + \alpha \times (\text{今天实测值} - \text{昨天平滑值})
\]
其中，\(\alpha\)（阿尔法）是介于 0~1 的小数（如 0.1 或 0.3），也叫“平滑系数”。

#### 8.2.2 生活类比：调温水洗澡
假设你想把水温调到 40度，但水管忽冷忽热。

- 昨天手感是 20度（旧平滑值）；
- 今天实测水温是 60度（新突刺）；
- 取 \(\alpha = 0.3\)（即我只相信新数据 30%）；
- 代入公式：今天手感 = 20 + 0.3 × (60 - 20) = **32度**。

看！虽然实测是 60度，但你只调到 32度。**你保留了 70% 的“历史记忆”，只接受了 30% 的“激进变化”**，剧烈抖动就这样被“压”下去了。

#### 8.2.3 为什么叫“指数”？（高中数学）
如果明天实测还是 60度，算出来是 32 + 0.3×(60-32) = 40.4度。
昨天的“20度”对今天的影响剩 70%，对后天只剩 49%（0.7²），对大后天只剩 34.3%（0.7³）……**越老的数据影响呈等比数列（指数级）衰减，无限趋近于 0**，但永不消失。

#### 8.2.4 参数 \(\alpha\) 怎么调？（工程师经验）
- **\(\alpha\) 越大（如 0.8）**：反应机敏，紧跟最新数据，但噪声残留多（适合游戏实时反馈）。
- **\(\alpha\) 越小（如 0.05）**：反应迟钝，极其平滑，但延迟大（适合计步器步数统计）。

---

### 8.3 四元数 Slerp（球面线性插值）：专治“三维方向转得生硬”

#### 8.3.1 为什么三维旋转不能用普通的“直线插值”（Lerp）？
- **普通 Lerp**（如 0° 和 90° 取中间 45°）只适用于平面直线。
- **三维旋转发生在球面上**！如果强行拉直线，物体会从球体内部“穿过去”，导致中途翻跟头或扭曲变形。
- **Slerp** 保证你的视角**贴着球面，沿着大圆（最短路径）均匀地飞过去**。

#### 8.3.2 公式拆解（看着吓人，实则只用了 sin 函数）
\[
\text{Slerp}(p, q, t) = \frac{\sin((1-t)\theta)}{\sin(\theta)} \times p + \frac{\sin(t\theta)}{\sin(\theta)} \times q
\]
- **p, q**：起点方向和终点方向（两个四元数）。
- **t**：进度（0~1，0为起点，1为终点）。
- **\(\theta\)（西塔）**：p 与 q 之间的**总夹角**（如北转东为 90°）。

**数学机制**：三角函数 \(\sin\) 会自动调整权重。
- 当 \(t=0\) 时，前半部分权重为 1，结果 = p（起点）。
- 当 \(t=1\) 时，后半部分权重为 1，结果 = q（终点）。
- 当 \(t=0.5\) 时，权重刚好落在**圆弧正中央**，保证**每秒旋转的角速度恒定**，且走最短路径。

### 8.4 🔥 硬核实战法则（100% 不搞混的“傻瓜判断法”）

> **直接结论：陀螺仪原始转速（角速度）绝对不能用 Slerp！只有当你把转速积分成“当前朝向方位”之后，才需要 Slerp。**

拿到一组数据，**只看单位**：

| 数据单位                            | 数据类型                            | 处理方案                            | 原因                                               |
| :---------------------------------- | :---------------------------------- | :---------------------------------- | :------------------------------------------------- |
| **°/s 或 rad/s**（每秒多少度/弧度） | **原始角速度**（瞬时快慢）          | **禁止 Slerp**，只配用 **EMA** 滤波 | 这是“车速表”，没有起点和终点，Slerp 会算出荒谬角度 |
| **° 或 rad**（且范围在 0~360°）     | **绝对朝向**（融合后的姿态/四元数） | **强烈推荐 Slerp**                  | 这是“当前位置”，在两个位置间过渡必须沿球面弧线     |

#### 8.4.1 三种具体场景拆解

**场景 1：必须用 Slerp 的数据**
- **融合后的旋转矢量**（手机系统算出的最终朝向）。
- 原因：磁力计易受金属干扰，朝向会瞬间跳变。Slerp 强制旧朝向**沿球面最短路径匀速“转”过去**，指南针箭头不会瞬移。

**场景 2：强烈建议用 Slerp 的数据**
- **游戏/AR 里的虚拟物体朝向**（如 ARKit 中的模型）。
- 原因：帧率不稳定时，Slerp 能补出中间缺失的旋转帧，防止模型像抽风一样乱翻跟头。

**场景 3：绝对不能碰 Slerp 的数据**
- **陀螺仪原始角速度**（CMRotationRate）。
- 类比：车速表显示 80km/h，你不能把 80 和 60 做 Slerp 来“平滑车速”——那叫匀速直线运动，放在旋转里会算出匪夷所思的错误角度。**原始转速只用 EMA 降噪**。

#### 8.4.2 手机里的真实世界案例（你一定见过）
- **地图蓝色箭头**：GPS 漂移导致箭头乱转时，系统底层用 Slerp 把箭头“拽”回正确方向。
- **横竖屏切换动画**：屏幕内容旋转的中间帧，就是用 Slerp 在 0° 和 90° 之间插值出来的。

### 8.6 完整代码实现（EMA + 四元数 Slerp）

#### 8.6.1 指数移动平均（EMA）工具类
```swift
class EMASmoother {
    private var smoothedValue: Double?
    var alpha: Double = 0.15 // 0~1，常用 0.1~0.3
    
    func smooth(_ newValue: Double) -> Double {
        guard let prev = smoothedValue else {
            smoothedValue = newValue
            return newValue
        }
        let result = prev * (1 - alpha) + newValue * alpha
        smoothedValue = result
        return result
    }
    
    func reset() { smoothedValue = nil }
}
```

#### 8.6.2 对欧拉角平滑（含相位展开，处理 ±π 跳变）
当必须使用欧拉角时，需对 yaw 做相位展开：
```swift
class SmoothMotionManager {
    static let shared = SmoothMotionManager()
    private let motionManager = CMMotionManager()
    private let queue = OperationQueue()
    
    private let rollSmoother = EMASmoother()
    private let pitchSmoother = EMASmoother()
    private let yawSmoother = EMASmoother()
    
    private var lastYaw: Double?
    private var yawOffset: Double = 0
    
    var alpha: Double = 0.15 {
        didSet {
            rollSmoother.alpha = alpha
            pitchSmoother.alpha = alpha
            yawSmoother.alpha = alpha
        }
    }
    
    private(set) var smoothRoll: Double = 0
    private(set) var smoothPitch: Double = 0
    private(set) var smoothYaw: Double = 0
    
    func startUpdates(interval: TimeInterval = 1.0/60.0) {
        guard motionManager.isDeviceMotionAvailable else { return }
        motionManager.deviceMotionUpdateInterval = interval
        motionManager.startDeviceMotionUpdates(using: .xArbitraryZVertical, to: queue) { [weak self] motion, _ in
            guard let self = self, let motion = motion else { return }
            let raw = motion.attitude
            
            self.smoothRoll = self.rollSmoother.smooth(raw.roll)
            self.smoothPitch = self.pitchSmoother.smooth(raw.pitch)
            
            // 对 yaw 做相位展开，防止 ±π 边界跳变
            var unwrapped = raw.yaw
            if let last = self.lastYaw {
                var delta = raw.yaw - last
                if delta > .pi { delta -= 2 * .pi }
                else if delta < -.pi { delta += 2 * .pi }
                self.yawOffset += delta
                unwrapped = raw.yaw - self.yawOffset
            } else {
                self.lastYaw = raw.yaw
            }
            self.smoothYaw = self.yawSmoother.smooth(unwrapped)
            self.lastYaw = raw.yaw
        }
    }
    
    func stop() {
        motionManager.stopDeviceMotionUpdates()
        rollSmoother.reset(); pitchSmoother.reset(); yawSmoother.reset()
        lastYaw = nil; yawOffset = 0
    }
}
```

#### 8.6.3 工业级方案：四元数 Slerp 平滑（强烈推荐用于 3D 旋转）
使用 Apple 的 `simd` 库，彻底避免欧拉角的所有缺陷：
```swift
import simd

class QuaternionSmoother {
    private var smoothQuat = simd_quatf(real: 1, imag: .zero)
    private var initialized = false
    var alpha: Float = 0.15
    
    func smooth(_ raw: simd_quatf) -> simd_quatf {
        if !initialized {
            smoothQuat = raw
            initialized = true
            return raw
        }
        // 确保两个四元数在同一半球（防止绕远路）
        let dot = dot(raw.vector, smoothQuat.vector)
        let rawAdjusted = dot < 0 ? simd_quatf(real: -raw.real, imag: -raw.imag) : raw
        smoothQuat = simd_slerp(smoothQuat, rawAdjusted, alpha)
        return smoothQuat
    }
}
```
> **生产提示**：四元数 Slerp 计算量虽略大于 EMA，但现代设备可在微秒级完成，放心用于 60fps 渲染循环。

## 九、常见问题与解决方案

| 问题           | 原因                            | 解决方案                        |
| -------------- | ------------------------------- | ------------------------------- |
| 应用崩溃       | 缺少 `NSMotionUsageDescription` | 在 Info.plist 中添加描述        |
| 无数据回调     | 模拟器不支持                    | 在真机上测试                    |
| 更新速率不稳定 | 多个 CMMotionManager 实例       | 使用单例                        |
| 内存泄漏       | 未弱引用 self 或未停止更新      | 使用 `[weak self]`，适时 `stop` |
| 后台无法采集   | 实时传感器不支持后台            | 使用计步器（全天候）或录制模式  |
| 角度跳变       | 欧拉角±π边界                    | 使用四元数 Slerp 或相位展开     |
| 平滑延迟过大   | α 值过小                        | 适当调大 α（如 0.3）            |

## 十、最佳实践总结

1. **性能优化**：
   - 使用 `xArbitraryCorrectedZVertical` 参考系。
   - 按需设置最低更新频率。
   - 整个应用只创建一个 `CMMotionManager`。
   - 及时停止更新以释放资源。

2. **数据准确性**：
   - 优先使用 `CMDeviceMotion` 的处理后数据。
   - 如需额外平滑，采用 EMA 或四元数 Slerp。
   - 注意时间戳对齐多模态数据。

3. **隐私合规**：
   - 提供清晰的 `NSMotionUsageDescription`。
   - 遵守数据隐私政策。

4. **架构设计**：
   - 封装 `MotionManager` 单例，统一管理。
   - 使用 `OperationQueue` 处理回调，避免主线程阻塞。
   - 上抛数据附带时间戳和必要的原始/平滑值。

5. **测试**：
   - 在真机上进行充分测试。
   - 验证不同设备、iOS 版本的兼容性。
