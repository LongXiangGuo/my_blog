# iOS 后台任务（BackgroundTasks）完全指南

## 一、简介

### 1.1 什么是 iOS 后台任务

现代 iOS 应用即使在未处于前台时，也需要执行一些工作——同步数据、更新小组件、或在锁定屏幕上通过 Live Activity 向用户推送信息。iOS 后台任务允许应用在未处于前台时执行工作，支持内容同步、数据处理和维护操作等场景。

在 iOS 13 之前，后台任务执行一直是个难题——开发者需要小心翼翼地在系统限制下工作，而用户则常常为电池续航担忧。苹果推出的 `BackgroundTasks` 框架彻底改变了这一局面，它提供了一套系统友好、高度节能的后台任务调度机制。

`BackgroundTasks` 框架是 Apple 官方提供的后台任务管理框架，**iOS 13.0+ / iPadOS 13.0+ / Mac Catalyst 13.1+ / tvOS 13.0+ / visionOS 1.0+** 可用。

`BGTaskScheduler` 是该框架的核心类，用于调度为应用最关键工作提供后台支持的任务。

### 1.2 为什么需要 BGTaskScheduler

- **电池续航至上**：iOS 始终将用户体验和电池寿命放在核心位置，对后台活动限制严格。
- **老方案的局限**：之前的 `Background Fetch` 和有限后台模式不够灵活、可控性差，开发者难以精准调度。
- **统一与优化**：`BGTaskScheduler` 旨在提供一个标准化、系统管理的后台任务入口，让系统能根据设备状态（是否充电、网络状况、用户活跃度等）智能调度任务，实现全局最优。

### 1.3 两种核心任务类型

iOS 提供两种主要的后台任务类型：

| 任务类型             | 用途                 | 时间限制 | 典型场景                                 |
| -------------------- | -------------------- | -------- | ---------------------------------------- |
| **BGAppRefreshTask** | 短任务，快速更新内容 | ~30 秒   | 获取最新数据、更新小组件、检查通知       |
| **BGProcessingTask** | 长任务，耗时操作     | 数分钟   | 数据库维护、机器学习模型更新、大数据同步 |

此外，**iOS 26** 引入了 `BGContinuedProcessingTask`，支持从前台开始、在后台继续执行的任务。

## 二、应用场景

### 2.1 BGAppRefreshTask 适用场景

- **内容刷新**：定期拉取最新的新闻、社交动态或股票行情
- **小组件更新**：为桌面小组件提供最新数据
- **轻量级数据同步**：同步少量的用户数据或配置
- **通知预检查**：在后台检查是否有新的推送通知

### 2.2 BGProcessingTask 适用场景

- **数据库维护**：清理过期数据、优化数据库索引
- **机器学习模型更新**：下载并更新 Core ML 模型
- **大文件同步**：上传/下载大量照片或文档
- **HealthKit 数据准备**：为健康研究准备必要数据

### 2.3 BGContinuedProcessingTask 适用场景（iOS 26+）

- **视频导出**：用户在前台开始导出，切换到后台后继续完成
- **大文件上传**：分块上传大文件，即使用户离开应用也能完成
- **计算密集型任务**：AI 推理、图像处理等需要较长时间的操作

### 3.2 架构设计原则

1. **任务声明**：应用在 `Info.plist` 中声明需要使用的后台任务类型及其唯一标识符
2. **任务注册**：应用启动时向 `BGTaskScheduler.shared` 注册每个任务标识符对应的处理程序
3. **系统智能调度**：系统根据全局因素决定何时触发任务
4. **有限时间窗口**：系统为任务分配有限的时间窗口执行
5. **任务管理**：通过 `expirationHandler` 处理超时，完成后必须调用 `setTaskCompleted(success:)`

## 四、实现原理

### 4.1 核心机制

`BGTaskScheduler` 的工作机制可以概括为以下五个步骤：

1. **任务声明**：在 `Info.plist` 中声明任务标识符
2. **任务注册**：应用启动时注册处理程序
3. **系统智能调度**：系统根据设备状态决定执行时机
4. **任务执行**：系统调用注册的处理程序
5. **任务管理**：处理超时并报告完成状态

### 4.2 系统调度决策因素

系统在决定是否执行后台任务时，会综合考虑以下因素：

- **电池电量**：低电量时可能延迟或跳过任务
- **网络可用性**：需要网络的任务会在网络可用时执行
- **用户活跃度**：设备闲置时更倾向于执行后台任务
- **充电状态**：连接电源时更可能执行耗电任务
- **应用使用模式**：用户频繁使用的应用获得更多后台执行机会

## 六、设计模式

### 6.1 单例模式（Singleton）

`BGTaskScheduler.shared` 提供了全局唯一的调度器实例，符合单例模式。

```swift
let scheduler = BGTaskScheduler.shared
```

### 6.2 注册-调度-执行模式（Register-Schedule-Execute）

这是 `BackgroundTasks` 框架的核心设计模式：
- **注册阶段**：应用启动时注册任务处理程序
- **调度阶段**：在适当时机提交任务请求
- **执行阶段**：系统在合适时机执行任务

### 6.3 策略模式（Strategy）

`BGContinuedProcessingTaskRequest` 的 `strategy` 属性允许开发者指定任务的调度策略。

### 6.4 观察者模式（Observer）

通过 `expirationHandler` 回调，系统可以在任务即将超时时通知应用进行清理操作。

### 6.5 模板方法模式（Template Method）

`BGTask` 作为抽象基类，定义了 `setTaskCompleted(success:)` 等模板方法，子类提供具体实现。

### 7.2 详细工作流程说明

**阶段一：配置与声明**
1. 在 Xcode 中启用 `Background Modes` 能力
2. 在 `Info.plist` 中添加 `BGTaskSchedulerPermittedIdentifiers` 数组

**阶段二：注册**
1. 应用启动时（`AppDelegate.didFinishLaunching` 或 `App.init`）注册任务
2. 调用 `BGTaskScheduler.shared.register(forTaskWithIdentifier:using:launchHandler:)`

**阶段三：调度**
1. 在适当时机（如应用进入后台）创建任务请求
2. 设置 `earliestBeginDate` 等参数
3. 调用 `BGTaskScheduler.shared.submit(request)` 提交

**阶段四：执行**
1. 系统在合适时机唤醒应用
2. 应用进程以 `.background` 状态启动
3. 执行注册的 `launchHandler`
4. 任务执行期间监听 `expirationHandler`
5. 完成后调用 `setTaskCompleted(success:)`

## 八、详细实现代码

### 8.1 Info.plist 配置

首先在 `Info.plist` 中声明任务标识符：

```xml
<key>BGTaskSchedulerPermittedIdentifiers</key>
<array>
    <string>com.yourcompany.app.refresh</string>
    <string>com.yourcompany.app.cleanup</string>
</array>
```

### 8.2 Xcode Capabilities 配置

1. 打开项目，选择 Target
2. 点击 **Signing & Capabilities**
3. 展开 **Background Modes**
4. 对于 `BGAppRefreshTask`，勾选 **Background fetch**
5. 对于 `BGProcessingTask`，勾选 **Background processing**

### 8.3 完整 Swift 实现

#### 8.3.1 App 入口注册（SwiftUI）

```swift
import BackgroundTasks
import SwiftUI

@main
struct MyApp: App {
    init() {
        // 注册 App Refresh 任务
        BGTaskScheduler.shared.register(
            forTaskWithIdentifier: "com.yourcompany.app.refresh",
            using: nil
        ) { task in
            self.handleAppRefresh(task: task as! BGAppRefreshTask)
        }
        
        // 注册 Processing 任务
        BGTaskScheduler.shared.register(
            forTaskWithIdentifier: "com.yourcompany.app.cleanup",
            using: nil
        ) { task in
            self.handleDatabaseCleanup(task: task as! BGProcessingTask)
        }
    }
    
    var body: some Scene {
        WindowGroup {
            ContentView()
        }
    }
    
    // ... 任务处理方法见下文
}
```

#### 8.3.2 App Delegate 注册（UIKit）

```swift
import BackgroundTasks
import UIKit

@main
class AppDelegate: UIResponder, UIApplicationDelegate {
    func application(
        _ application: UIApplication,
        didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]?
    ) -> Bool {
        // 注册 App Refresh 任务
        BGTaskScheduler.shared.register(
            forTaskWithIdentifier: "com.yourcompany.app.refresh",
            using: nil
        ) { task in
            guard let refreshTask = task as? BGAppRefreshTask else {
                task.setTaskCompleted(success: false)
                return
            }
            self.handleAppRefresh(task: refreshTask)
        }
        
        // 注册 Processing 任务
        BGTaskScheduler.shared.register(
            forTaskWithIdentifier: "com.yourcompany.app.cleanup",
            using: nil
        ) { task in
            guard let processingTask = task as? BGProcessingTask else {
                task.setTaskCompleted(success: false)
                return
            }
            self.handleDatabaseCleanup(task: processingTask)
        }
        
        // 首次调度（可选）
        scheduleAppRefresh()
        scheduleDatabaseCleanup()
        
        return true
    }
}
```

#### 8.3.3 调度 BGAppRefreshTask

```swift
func scheduleAppRefresh() {
    let request = BGAppRefreshTaskRequest(
        identifier: "com.yourcompany.app.refresh"
    )
    // 最早开始时间：15分钟后
    request.earliestBeginDate = Date(timeIntervalSinceNow: 15 * 60)
    
    do {
        try BGTaskScheduler.shared.submit(request)
    } catch {
        print("调度刷新任务失败: \(error.localizedDescription)")
    }
}
```

#### 8.3.4 调度 BGProcessingTask

```swift
func scheduleDatabaseCleanup() {
    let request = BGProcessingTaskRequest(
        identifier: "com.yourcompany.app.cleanup"
    )
    // 要求网络连接
    request.requiresNetworkConnectivity = true
    // 要求外接电源（省电）
    request.requiresExternalPower = true
    // 最早开始时间：1小时后
    request.earliestBeginDate = Date(timeIntervalSinceNow: 60 * 60)
    
    do {
        try BGTaskScheduler.shared.submit(request)
    } catch {
        print("调度清理任务失败: \(error.localizedDescription)")
    }
}
```

#### 8.3.5 处理 BGAppRefreshTask

```swift
func handleAppRefresh(task: BGAppRefreshTask) {
    // 立即为下一次调度做准备
    scheduleAppRefresh()
    
    // 创建可取消的异步任务
    let refreshTask = Task {
        do {
            // 执行数据获取
            let data = try await DataService.shared.fetchLatest()
            await MainActor.run {
                DataStore.shared.update(with: data)
            }
            task.setTaskCompleted(success: true)
        } catch {
            task.setTaskCompleted(success: false)
        }
    }
    
    // 设置过期处理程序
    task.expirationHandler = {
        refreshTask.cancel()
        task.setTaskCompleted(success: false)
    }
}
```

#### 8.3.6 处理 BGProcessingTask

```swift
func handleDatabaseCleanup(task: BGProcessingTask) {
    let cleanupTask = Task {
        do {
            // 执行数据库清理
            try await DatabaseService.shared.cleanupExpiredRecords()
            try await DatabaseService.shared.optimizeIndexes()
            task.setTaskCompleted(success: true)
        } catch {
            task.setTaskCompleted(success: false)
        }
    }
    
    task.expirationHandler = {
        cleanupTask.cancel()
        // 保存进度以便下次恢复
        ProgressManager.shared.saveCurrentProgress()
        task.setTaskCompleted(success: false)
    }
}
```

#### 8.3.7 BGContinuedProcessingTask（iOS 26+）

```swift
import BackgroundTasks

@available(iOS 26.0, *)
func scheduleContinuedProcessing() {
    let request = BGContinuedProcessingTaskRequest(
        identifier: "com.yourcompany.app.export"
    )
    // 设置策略
    request.strategy = .immediate // 或 .opportunistic
    request.earliestBeginDate = Date()
    
    do {
        try BGTaskScheduler.shared.submit(request)
    } catch {
        print("调度持续处理任务失败: \(error)")
    }
}

@available(iOS 26.0, *)
func handleContinuedProcessing(task: BGContinuedProcessingTask) {
    // 系统会通过 Live Activity 显示进度
    let exportTask = Task {
        for progress in stride(from: 0, through: 1.0, by: 0.1) {
            // 更新进度（会反映在 Live Activity 中）
            task.progress = progress
            try await Task.sleep(nanoseconds: 1_000_000_000)
        }
        task.setTaskCompleted(success: true)
    }
    
    task.expirationHandler = {
        exportTask.cancel()
        task.setTaskCompleted(success: false)
    }
}
```

| `requiresNetworkConnectivity`         | `BGProcessingTaskRequest` | 是否需要网络连接         | `false`                         |
| `requiresExternalPower`               | `BGProcessingTaskRequest` | 是否需要外接电源         | `false`                         |
| `BGAppRefreshTask` 时间限制           | -                         | 后台运行时间上限         | ~30 秒                          |
| `BGProcessingTask` 时间限制           | -                         | 后台运行时间上限         | 数分钟                          |
| `BGTaskSchedulerPermittedIdentifiers` | `Info.plist`              | 允许的后台任务标识符列表 | 必须配置                        |
| `UIBackgroundModes`                   | `Info.plist`              | 后台模式配置             | `fetch` / `processing`          |
| 最大待处理任务数                      | 系统限制                  | 同时可调度的任务数量     | 1 个 Refresh + 10 个 Processing |

## 十、常见问题与解决方案

### 10.1 任务未执行

**问题**：提交的任务从未被执行。

**可能原因与解决方案**：
- `Info.plist` 中未正确配置 `BGTaskSchedulerPermittedIdentifiers`
- 未在 Xcode Capabilities 中启用对应的 Background Mode
- 任务标识符不匹配（注册时与提交时不一致）
- 系统资源紧张，任务被延迟或跳过

### 10.2 任务执行时间过短

**问题**：`BGAppRefreshTask` 实际执行时间远小于 30 秒。

**解决方案**：
- 将耗时操作移至 `BGProcessingTask`
- 使用 `URLSession` 的后台传输服务处理大文件下载
- 将长任务拆分为多个短任务链

### 10.3 任务调度失败 - tooManyPendingTaskRequests

**问题**：提交任务时抛出 `tooManyPendingTaskRequests` 错误。

**解决方案**：
- 最多同时调度 1 个 Refresh 任务和 10 个 Processing 任务
- 取消不再需要的待处理任务：`BGTaskScheduler.shared.cancel(taskRequestWithIdentifier:)`
- 确保任务完成后正确调用 `setTaskCompleted(success:)`

### 10.4 任务调度失败 - notPermitted

**问题**：提交任务时抛出 `notPermitted` 错误。

**解决方案**：
- 检查 `Info.plist` 中是否正确配置了 `BGTaskSchedulerPermittedIdentifiers`
- 检查 Xcode Capabilities 中是否启用了对应的 Background Mode

### 10.5 强制退出后任务行为

**问题**：用户强制退出应用后，后台任务是否还会执行。

**说明**：当用户从 App Switcher 中强制退出应用后，`BGProcessingTask` 仍可能执行一次，之后系统会忽略该应用的任务，直到用户再次打开应用。这是 iOS 的系统设计行为，无法规避。

### 10.6 模拟器不支持

**问题**：在模拟器上无法测试后台任务。

**解决方案**：后台任务必须在真实设备上进行测试。可以使用 Xcode 的 `_simulateLaunchForTaskWithIdentifier:` 方法在模拟器上手动触发。

### 10.7 BGContinuedProcessingTask 问题（iOS 26）

**问题**：`BGContinuedProcessingTask` 在 iOS 26 正式版中不工作。

**解决方案**：
- 确保在 iOS 26+ 设备上测试
- 检查是否正确配置了 Background GPU Access 权限（如需要）
- 关注 Apple 官方的更新和修复

## 十一、最佳实践

### 11.1 任务设计原则

1. **设计短小精悍的任务**：每个任务步骤应在 5 秒内完成，长任务应拆分为多个粒度步骤
2. **合理使用任务链**：将复杂任务拆分为多个可独立执行的小任务
3. **考虑任务必要性**：非核心功能避免后台执行

### 11.2 性能与功耗优化

1. **在低使用时段调度**：在设备充电或连接 Wi-Fi 时执行任务
2. **批量处理相似任务**：减少资源使用
3. **渐进式重试**：失败任务使用逐渐延长的重试间隔
4. **减少任务提交频率**：避免频繁提交任务
5. **及时释放资源**：任务完成后立即释放资源

### 11.3 可靠性保障

1. **始终实现 `expirationHandler`**：处理系统超时信号，保存进度
2. **任务完成后必须调用 `setTaskCompleted(success:)`**：告知系统任务状态
3. **在任务开始时立即重新调度下一次**：确保连续性
4. **使用检查点保存进度**：便于任务中断后恢复
5. **结合多种后台机制**：`BGTaskScheduler` + `Background URLSession` + Silent Push

### 11.4 测试建议

1. **在真实设备上测试**：模拟器不支持后台任务
2. **使用 Xcode 调试功能**：通过 `_simulateLaunchForTaskWithIdentifier:` 手动触发
3. **测试各种系统状态**：低电量、网络断开、设备锁定等场景
4. **使用 TestFlight 验证**：确保在生产环境中正常工作

### 11.5 代码组织建议

1. **集中管理任务标识符**：使用常量或枚举统一管理
2. **封装任务调度逻辑**：创建专门的 `BackgroundTaskManager` 类
3. **使用 Swift Concurrency**：利用 `async/await` 处理异步操作
4. **做好错误日志记录**：便于排查问题

## 总结

iOS 的 `BackgroundTasks` 框架为开发者提供了一套系统级、高效节能的后台任务管理方案。通过合理使用 `BGAppRefreshTask`、`BGProcessingTask` 以及 iOS 26 引入的 `BGContinuedProcessingTask`，开发者可以在保证用户体验和电池续航的前提下，实现丰富的数据同步、内容更新和计算密集型任务。

理解系统的调度机制、遵循最佳实践、正确处理任务生命周期，是构建高质量后台任务的关键。随着 iOS 系统的不断演进，后台任务 API 也在持续完善，开发者应持续关注 Apple 官方的更新和 WWDC 的最新内容。
