# AVFoundation 完全指南

## 一、AVFoundation 整体架构

### 1.1 在系统层级中的位置

AVFoundation 是 Apple 平台上处理基于时间的视听媒体的**高级框架**。它在整个 iOS/macOS 媒体技术栈中处于中间层：

| 层级       | 框架                                 | 职责                                         |
| ---------- | ------------------------------------ | -------------------------------------------- |
| 高层       | AVKit / UIKit                        | 即用型播放器 UI、系统相机控制器              |
| **中间层** | **AVFoundation**                     | **媒体播放、采集、编辑、处理**               |
| 底层       | Core Audio / Core Video / Core Media | 音频/视频底层数据处理、CMTime 等原始数据类型 |
| 硬件层     | 硬件编解码器、GPU                    | 硬件加速编解码与渲染                         |

Core Media 提供了 AVFoundation 所用的低层级数据类型和接口，包括基于 `CMTime` 的时基模型。Core Audio 提供音频录制/播放的底层支持，Core Video 提供视频帧的缓存和像素格式转换支持。

### 1.2 功能单元划分

AVFoundation 包含 100 多个类，可以按功能单元进行拆分理解：

1. **音频播放和录制**：`AVAudioPlayer`、`AVAudioRecorder`
2. **媒体检查**：`AVAsset`、`AVMetadataItem`
3. **视频播放**：`AVPlayer`、`AVPlayerItem`
4. **媒体采集**：`AVCaptureSession`
5. **媒体编辑**：`AVMutableComposition`
6. **媒体处理**：`AVAssetReader`、`AVAssetWriter`

> **最佳实践**：应使用可用的最高层级抽象。如果只是想播放视频，使用 AVKit 框架；如果只需最少格式控制来录制视频，使用 `UIImagePickerController`。


## 二、类图结构与核心类

### 2.1 核心类继承关系

```
AVAsset (抽象基类)
├── AVURLAsset          // 从 URL 加载媒体
├── AVComposition       // 媒体合成（不可变）
│   └── AVMutableComposition  // 可变的媒体合成
└── AVAssetTrack        // 单个轨道的表示
    └── AVMutableCompositionTrack

AVPlayerItem            // 资产的播放状态
├── AVPlayerItemTrack   // 单个轨道的播放状态
└── (被 AVPlayer 使用)

AVPlayer                // 播放控制器
└── AVQueuePlayer       // 队列播放

AVCaptureSession        // 采集会话
├── AVCaptureDeviceInput    // 输入（摄像头/麦克风）
└── AVCaptureOutput         // 输出（文件/预览/数据）
    ├── AVCaptureMovieFileOutput
    ├── AVCaptureVideoDataOutput
    └── AVCapturePhotoOutput
```

### 2.2 核心类详解

**AVAsset** — 框架的核心，是框架设计的出发点。它是**一个或多个媒体数据集合的聚合表示**，提供标题、时长、自然呈现尺寸等信息。`AVAsset` 不依赖特定数据格式，是其他资产类的超类。

**AVAssetTrack** — 资产中每一部分媒体数据属于统一类型，称为轨道（Track）。典型情况下一轨代表音频，另一轨代表视频。

**AVPlayerItem** — 将资产的**呈现状态**与资产本身分离。这允许你同时播放同一资产的两个不同片段，且可用不同分辨率渲染。

**AVCaptureSession** — 采集系统的中心协调者，管理输入与输出设备之间的数据流。


## 三、实现原理

### 3.1 异步加载机制

AVFoundation 的一个重要设计理念是：**初始化资产或轨道并不意味着它已准备好使用**。计算时长等信息可能需要时间（如 MP3 文件可能不包含摘要信息）。解决方案是通过 **Block 回调异步获取值**，而非阻塞当前线程。

所有遵循 `AVAsynchronousKeyValueLoading` 协议的类都支持这种异步加载模式。

### 3.2 多线程与性能优化

AVFoundation 高度依赖多线程机制，充分利用多核硬件优势，大量使用 **Block 和 GCD**。采集会话建议在专用串行 DispatchQueue 中配置，避免 UI 卡顿。

### 3.3 硬件加速

AVFoundation 为视频播放和捕获提供了**硬件加速机制**来优化整个流程。在视频编辑和播放过程中，还可以利用 Core Animation 添加动画标题和图片效果。


## 四、设计模式

### 4.1 面向轨道（Track-Based）设计

编辑系统的架构是**面向轨道的**，允许像非线性编辑软件（如 Final Cut Pro）一样灵活操作音视频片段。编辑流程为：

```
AVAsset → AVMutableComposition → AVMutableCompositionTrack 
→ [AVMutableVideoComposition] → AVAssetExportSession
```

### 4.2 会话（Session）模式

`AVCaptureSession` 作为所有采集活动的汇集点，协调输入和输出的数据流动。数据流向为：

```
设备 → 输入(Input) → Session → 输出(Output) → 处理/展示
```

### 4.3 协议驱动设计

AVFoundation 大量使用 Protocol 来定义可扩展的能力。例如 `AVVideoCompositing` 协议允许实现自定义视频合成器。

### 4.4 工厂与构建器模式

通过 `AVCaptureDeviceInput(device:)` 等工厂方法创建输入对象，通过 `AVMutableComposition` 的 `addMutableTrack` 方法构建轨道。

### 4.5 观察者模式

通过 KVO 观察 `AVPlayerItem` 的 `status`、`loadedTimeRanges` 等属性变化，实现播放状态监控。


## 五、工作流程

### 5.1 视频播放流程

```
1. 创建 AVURLAsset(url:)
2. 创建 AVPlayerItem(asset:)
3. 创建 AVPlayer(playerItem:)
4. 创建 AVPlayerLayer(player:)
5. 调用 player.play()
```

播放器将资产的呈现状态与资产本身分离，通过 `AVPlayerItem` 管理播放状态。

### 5.2 媒体采集流程

```
1. 创建 AVCaptureSession()
2. 获取 AVCaptureDevice（摄像头/麦克风）
3. 创建 AVCaptureDeviceInput
4. 创建 AVCaptureOutput（文件输出/数据输出/照片输出）
5. 添加输入和输出到 Session（先检查 canAddInput/Output）
6. 在专用队列调用 session.startRunning()
7. 处理输出回调或保存文件
```

`AVCaptureSession` 可同时管理多个输入输出（如前后摄像头切换、同时采集视频与音频）。

### 5.3 媒体编辑流程

```
1. 创建 AVMutableComposition()
2. 添加可变轨道 (addMutableTrack)
3. 从 AVAsset 获取 AVAssetTrack
4. 将片段插入轨道 (insertTimeRange:of:at:)
5. [可选] 配置 AVMutableVideoComposition（转场/水印）
6. 创建 AVAssetExportSession 导出
```

编辑操作归根结底都是：把多个 AVAsset 的音视频轨道插入到 `AVMutableComposition` 对应轨道中。


## 六、具体用法与使用场景

### 6.1 场景一：视频播放

```swift
import AVFoundation
import AVKit

class VideoPlayerViewController: UIViewController {
    var player: AVPlayer?
    var playerLayer: AVPlayerLayer?
    
    override func viewDidLoad() {
        super.viewDidLoad()
        
        guard let url = Bundle.main.url(forResource: "sample", withExtension: "mp4") else {
            return
        }
        
        let asset = AVURLAsset(url: url)
        let playerItem = AVPlayerItem(asset: asset)
        player = AVPlayer(playerItem: playerItem)
        
        playerLayer = AVPlayerLayer(player: player)
        playerLayer?.frame = view.bounds
        playerLayer?.videoGravity = .resizeAspect
        view.layer.addSublayer(playerLayer!)
        
        // 观察播放状态
        playerItem.addObserver(self, forKeyPath: #keyPath(AVPlayerItem.status), 
                               options: [.new, .initial], context: nil)
    }
    
    override func observeValue(forKeyPath keyPath: String?, of object: Any?, 
                               change: [NSKeyValueChangeKey : Any]?, context: UnsafeMutableRawPointer?) {
        if keyPath == #keyPath(AVPlayerItem.status) {
            if let item = object as? AVPlayerItem, item.status == .readyToPlay {
                player?.play()
            }
        }
    }
}
```

### 6.2 场景二：视频采集与录制

```swift
import AVFoundation

class CameraController: NSObject {
    private let session = AVCaptureSession()
    private var movieOutput = AVCaptureMovieFileOutput()
    private var previewLayer: AVCaptureVideoPreviewLayer?
    
    func setupCamera() throws {
        // 1. 配置 session
        session.sessionPreset = .high
        
        // 2. 获取摄像头
        guard let camera = AVCaptureDevice.default(.builtInWideAngleCamera, 
                                                   for: .video, 
                                                   position: .back) else {
            throw NSError(domain: "Camera", code: -1)
        }
        
        // 3. 创建输入
        let cameraInput = try AVCaptureDeviceInput(device: camera)
        if session.canAddInput(cameraInput) {
            session.addInput(cameraInput)
        }
        
        // 4. 创建音频输入
        guard let microphone = AVCaptureDevice.default(for: .audio) else {
            throw NSError(domain: "Microphone", code: -2)
        }
        let audioInput = try AVCaptureDeviceInput(device: microphone)
        if session.canAddInput(audioInput) {
            session.addInput(audioInput)
        }
        
        // 5. 创建输出
        if session.canAddOutput(movieOutput) {
            session.addOutput(movieOutput)
        }
        
        // 6. 预览层
        previewLayer = AVCaptureVideoPreviewLayer(session: session)
        previewLayer?.videoGravity = .resizeAspectFill
    }
    
    func startRecording(to url: URL) {
        guard movieOutput.isRecording == false else { return }
        movieOutput.startRecording(to: url, recordingDelegate: self)
    }
    
    func stopRecording() {
        guard movieOutput.isRecording else { return }
        movieOutput.stopRecording()
    }
    
    func startSession() {
        DispatchQueue.global(qos: .userInitiated).async {
            self.session.startRunning()
        }
    }
}

extension CameraController: AVCaptureFileOutputRecordingDelegate {
    func fileOutput(_ output: AVCaptureFileOutput, 
                    didFinishRecordingTo outputFileURL: URL, 
                    from connections: [AVCaptureConnection], 
                    error: Error?) {
        // 处理录制完成
    }
}
```

### 6.3 场景三：视频剪辑与合成

```swift
import AVFoundation

func mergeVideos(videoURLs: [URL], outputURL: URL, completion: @escaping (Bool, Error?) -> Void) {
    let composition = AVMutableComposition()
    
    guard let videoTrack = composition.addMutableTrack(withMediaType: .video, 
                                                        preferredTrackID: kCMPersistentTrackID_Invalid),
          let audioTrack = composition.addMutableTrack(withMediaType: .audio, 
                                                        preferredTrackID: kCMPersistentTrackID_Invalid) else {
        completion(false, nil)
        return
    }
    
    var currentTime = CMTime.zero
    
    for url in videoURLs {
        let asset = AVURLAsset(url: url)
        guard let assetVideoTrack = asset.tracks(withMediaType: .video).first,
              let assetAudioTrack = asset.tracks(withMediaType: .audio).first else {
            continue
        }
        
        let duration = asset.duration
        try? videoTrack.insertTimeRange(CMTimeRangeMake(start: .zero, duration: duration),
                                        of: assetVideoTrack,
                                        at: currentTime)
        try? audioTrack.insertTimeRange(CMTimeRangeMake(start: .zero, duration: duration),
                                        of: assetAudioTrack,
                                        at: currentTime)
        currentTime = CMTimeAdd(currentTime, duration)
    }
    
    guard let exportSession = AVAssetExportSession(asset: composition, 
                                                   presetName: AVAssetExportPresetHighestQuality) else {
        completion(false, nil)
        return
    }
    
    exportSession.outputURL = outputURL
    exportSession.outputFileType = .mp4
    exportSession.shouldOptimizeForNetworkUse = true
    
    exportSession.exportAsynchronously {
        DispatchQueue.main.async {
            completion(exportSession.status == .completed, exportSession.error)
        }
    }
}
```

## 八、常见坑与避坑指南

### 8.1 权限相关

**坑**：录制或采集时 `record()` 返回 false 或采集失败。

**解决**：
- 在 Info.plist 中添加 `NSCameraUsageDescription` 和 `NSMicrophoneUsageDescription`
- 使用 `AVCaptureDevice.requestAccess(for:)` 请求权限
- 检查 `AVAuthorizationStatus` 状态

### 8.2 Session 配置

**坑**：在非专用队列配置 Session 导致 UI 卡顿。

**解决**：在专用串行 DispatchQueue 中配置和启动 Session：
```swift
let sessionQueue = DispatchQueue(label: "session queue", qos: .userInitiated)
sessionQueue.async {
    self.session.startRunning()
}
```

### 8.3 轨道时间对齐

**坑**：轨道片段未对齐，导致黑帧或画面错乱。

**解决**：注意 `CMTime` 的精度问题，使用 `CMTimeMake` 时注意分母的选择。视频合成中不要在各片段间留空隙。

### 8.4 播放器内存问题

**坑**：播放远程媒体时，把整个文件先下载到内存再交给播放器，导致内存暴涨甚至 App 被杀。

**解决**：使用 `AVPlayer` 直接播放 URL，它支持流式播放和 HLS。

### 8.5 轨道数量过多

**坑**：使用过多 `AVMutableCompositionTrack` 导致播放失败。

**解决**：避免为每个视频片段创建单独的轨道，尽量复用轨道，或限制同时使用的轨道数量。

### 8.6 视频合成中的静态帧问题

**坑**：将 `AVMutableVideoComposition.frameDuration` 设置为资产的总时长，导致只产生一帧然后被"保持"。

**解决**：`frameDuration` 应设置为每帧的持续时间（如 1/30 秒），而非总时长。

### 8.7 导出失败

**坑**：`AVAssetExportSession` 导出失败，错误码 -11800 等。

**解决**：
- 检查输出路径是否有写入权限
- 确保 `outputFileType` 与预设匹配
- 检查资产是否可导出 (`asset.isExportable`)

### 8.8 API 废弃

**坑**：iOS 26 后部分 API 被废弃。

**解决**：
- 在 Xcode Build Settings 中启用 Deprecated Functions 警告
- 关注 WWDC 的 AVFoundation 更新

### 8.9 录制视频开头黑帧

**坑**：录制视频开头或结尾出现黑帧。

**解决**：在用户按下录制按钮之前就配置好 `AVCaptureMovieFileOutput`，而不是按下时才配置。

### 8.10 委托方法未被调用

**坑**：`AVContentKeySessionDelegate` 等方法未被调用。

**解决**：
- 确认代理已设置并实现了必要的方法
- 检查会话状态和密钥请求流程是否正确启动
- 查看控制台输出获取错误信息


## 九、调试建议

Apple 官方提供了技术笔记 TN2447 专门讨论 AVFoundation 合成、视频合成和音频混合的调试：

1. **可视化 Composition**：将合成内容可视化输出，检查轨道对齐情况
2. **检查轨道段对齐**：确保所有轨道段在时间轴上正确对齐
3. **检查图层变换**：变换矩阵错误可能导致内容超出边界
4. **使用断言**：在关键位置添加断言验证状态
5. **日志输出**：打印 `CMTime`、轨道 ID 等关键信息

# Apple 媒体与音频框架完全指南

Apple 平台提供了十余个媒体相关的框架，它们分层协作，共同构成了从底层硬件访问到上层应用交互的完整媒体技术栈。以下逐一解析每个框架，并总结它们之间的关系和使用场景。


## 一、框架分层总览

在深入每个框架之前，先理解它们在整体架构中的位置：

```
┌─────────────────────────────────────────────────────────────┐
│                    应用层 (App Layer)                       │
│  MusicKit  │  ReplayKit  │  Speech  │  SoundAnalysis       │
├─────────────────────────────────────────────────────────────┤
│                   媒体服务层 (Media Services)               │
│  AVFoundation  │  MediaPlayer  │  AudioToolbox             │
├─────────────────────────────────────────────────────────────┤
│                   核心媒体层 (Core Media)                   │
│  Core Audio  │  Core Media  │  VideoToolbox               │
├─────────────────────────────────────────────────────────────┤
│                     硬件抽象层 (HAL)                        │
│              音频硬件  │  视频硬件  │  Neural Engine        │
└─────────────────────────────────────────────────────────────┘
```

iOS 音频开发提供了多层次的技术架构，开发者可根据需求选择不同层级的解决方案。


## 二、其它音视频框架详细解析

### 2.1 Core Audio — 数字音频基础设施

**定位**：最底层的音频框架，所有 iOS 音频开发的基础。

**架构**：Core Audio 是 iOS 和 macOS 的数字音频基础设施，包含一组用于处理应用程序音频需求的软件框架。它使用硬件抽象层（HAL）为应用程序与硬件交互提供一致且可预测的接口。

**核心组件**：
- **Audio Units**：可组合的音频处理模块，有五种基本单元类型：输入单元（如 AURemoteIO）、输出单元、混音单元、效果单元和生成器单元
- **Audio Queue Services**：处理基本的音频播放和录音功能
- **Audio Converter Services**：音频格式转换
- **Audio File Services**：音频文件读写

**设计模式**：
- **属性-值模式**：Core Audio 采用属性对机制来管理和操作音频对象的状态和行为，每个属性 KEY 是助记名字定义的枚举常量
- **组合模式**：Audio Unit 可组合成处理链，典型处理链包含输入单元 → 效果单元 → 输出单元
- **回调模式**：通过 renderBlock 闭包在音频线程中处理数据

**工作流程**（音频采集与播放）：
```
1. 创建 AudioComponentDescription 描述所需单元类型
2. 使用 AudioComponentFindNext 查找组件
3. 使用 AudioComponentInstanceNew 创建实例
4. 配置单元属性（采样率、缓冲区大小等）
5. 实现 renderBlock 处理音频数据
6. 启动音频单元
7. 在 renderBlock 中实时处理数据
8. 停止并释放资源
```

**核心类/结构**：
| 类型 | 名称                          | 说明                         |
| ---- | ----------------------------- | ---------------------------- |
| 结构 | `AudioStreamBasicDescription` | 音频流格式描述               |
| 结构 | `AudioTimeStamp`              | 音频时间戳                   |
| 枚举 | `AudioObjectPropertySelector` | 属性选择器                   |
| 类   | `AUAudioUnit`                 | 音频单元（Objective-C 封装） |

**使用场景**：
- 需要**极低延迟**的实时音频处理（VoIP、乐器 App、游戏音效）
- 自定义音频效果器（均衡器、混响、压缩器）
- 音频合成（虚拟乐器）
- 多路音频混音

**代码示例**（创建 RemoteIO 音频单元）：
```swift
import AudioToolbox

func setupAudioUnit() {
    var componentDesc = AudioComponentDescription(
        componentType: kAudioUnitType_Output,
        componentSubType: kAudioUnitSubType_RemoteIO,
        componentManufacturer: kAudioUnitManufacturer_Apple,
        componentFlags: 0,
        componentFlagsMask: 0
    )
    
    guard let component = AudioComponentFindNext(nil, &componentDesc) else {
        fatalError("找不到 RemoteIO 单元")
    }
    
    var audioUnit: AudioUnit?
    let status = AudioComponentInstanceNew(component, &audioUnit)
    guard status == noErr else { fatalError("创建音频单元失败") }
    
    // 启用输入输出
    var enableIO: UInt32 = 1
    AudioUnitSetProperty(audioUnit!,
                         kAudioOutputUnitProperty_EnableIO,
                         kAudioUnitScope_Input, 1,
                         &enableIO, UInt32(MemoryLayout<UInt32>.size))
    
    // 设置音频格式（44.1kHz 或 48kHz）
    // 设置缓冲区大小
}
```

**常见坑**：
1. **实时线程限制**：renderBlock 在实时音频线程执行（`com.apple.audio.IOThread`），该线程具有最高优先级。处理逻辑必须在 1-2ms 内完成，**禁止**任何阻塞操作、内存分配、锁机制或 Objective-C 消息派发
2. **属性设置顺序**：必须先设置单元属性再初始化，否则可能无效
3. **双通道配置**：必须同时启用输入和输出通道（kAudioOutputUnitProperty_EnableIO）


### 2.2 Core Media — 媒体管道基础

**定位**：定义 AVFoundation 及其他高层媒体框架所使用的媒体管道。

**架构**：Core Media 是基于 C 的底层框架，提供了处理 iOS 和 macOS 媒体栈的关键功能。它定义时间、媒体样本和媒体队列等基本数据类型，上层框架构建于此之上。

**设计模式**：
- **值对象模式**：`CMTime`、`CMTimeRange`、`CMTimeMapping` 是不可变的值类型结构体
- **有理数表示模式**：时间用分数表示（value/timescale），避免浮点精度问题

**核心数据结构**：
| 类型                     | 说明                                           |
| ------------------------ | ---------------------------------------------- |
| `CMTime`                 | 有理数表示的时间（value 分子，timescale 分母） |
| `CMTimeRange`            | 时间范围（start + duration）                   |
| `CMTimeMapping`          | 源时间范围到目标时间范围的映射                 |
| `CMSampleBuffer`         | 包含零个或多个统一媒体类型的样本               |
| `CMBlockBuffer`          | 在系统中移动内存块                             |
| `CMClock` / `CMTimebase` | 时钟和时间线管理                               |

**CMTime 详解**：
```swift
// CMTime 结构（C 语言）
typedef struct {
    CMTimeValue value;      // 分子，64位有符号整数
    CMTimeScale timescale;  // 分母，32位有符号整数
    CMTimeFlags flags;      // 状态标志
    CMTimeEpoch epoch;      // 时间纪元
} CMTime;

// 创建方式
let time1 = CMTime(value: 1, timescale: 30)  // 1/30 秒
let time2 = CMTime(seconds: 0.5, preferredTimescale: 600)
let time3 = CMTimeMake(value: 3000, timescale: 600)  // 5秒

// 特殊值
let zero = CMTime.zero
let invalid = CMTime.invalid
let positiveInfinity = CMTime.positiveInfinity
```

**工作流程**（时间处理）：
```
1. 使用 CMTimeMake 创建时间点或持续时间
2. 使用 CMTimeAdd/Subtract 进行时间运算
3. 使用 CMTimeCompare 比较时间
4. 使用 CMTimeRangeMake 创建时间范围
5. 使用 CMTimeRangeContainsTime 判断包含关系
```

**使用场景**：
- 作为所有音视频框架的**时间基础设施**
- 精确控制媒体播放、编辑的时间点
- 媒体样本的时间戳管理

**常见坑**：
1. **浮点数陷阱**：不要用 Double 直接表示时间，使用 CMTime 避免精度丢失
2. **分母选择**：timescale 应足够大以保持精度（如 600 或 1000），但不要过大导致溢出
3. **有效性检查**：使用 `CMTIME_IS_VALID` 宏检查时间是否有效


### 2.3 VideoToolbox — 硬件视频编解码

**定位**：提供对硬件编码器和解码器的直接访问。

**架构**：VideoToolbox 是低层框架，提供视频压缩和解压缩服务，以及 CoreVideo 像素缓冲区中光栅图像格式之间的转换。服务以会话对象（压缩、解压缩、像素传输）的形式提供，作为 Core Foundation（CF）类型提供。

**核心会话对象**：
| 类型                     | 说明             |
| ------------------------ | ---------------- |
| `VTCompressionSession`   | 视频压缩会话     |
| `VTDecompressionSession` | 视频解压缩会话   |
| `VTPixelTransferSession` | 像素格式转换会话 |

**设计模式**：
- **会话模式**：通过会话对象管理编解码生命周期
- **回调模式**：编码/解码完成后通过回调返回数据
- **工厂模式**：通过 `VTCompressionSessionCreate` 等函数创建会话

**工作流程**（视频硬编码）：
```
1. VTCompressionSessionCreate 创建编码会话
2. VTSessionSetProperty 设置编码参数（分辨率、帧率、比特率）
3. VTCompressionSessionPrepareToEncodeFrames 准备编码
4. 循环获取采集数据
5. VTCompressionSessionEncodeFrame 编码帧
6. 在编码回调中获取编码后数据
7. 将数据写入 H.264/H.265 文件
8. VTCompressionSessionInvalidate 释放会话
```

**代码示例**（H.264 硬编码）：
```swift
import VideoToolbox
import CoreMedia

// 创建编码会话
var session: VTCompressionSession?
let status = VTCompressionSessionCreate(
    allocator: nil,
    width: 1920,
    height: 1080,
    codecType: kCMVideoCodecType_H264,
    encoderSpecification: nil,
    imageBufferAttributes: nil,
    compressedDataAllocator: nil,
    outputCallback: nil,
    refcon: nil,
    compressionSessionOut: &session
)

// 设置参数
VTSessionSetProperty(session!, key: kVTCompressionPropertyKey_ProfileLevel,
                     value: kVTProfileLevel_H264_High_AutoLevel)
VTSessionSetProperty(session!, key: kVTCompressionPropertyKey_AverageBitRate,
                     value: NSNumber(value: 2_000_000))
VTSessionSetProperty(session!, key: kVTCompressionPropertyKey_ExpectedFrameRate,
                     value: NSNumber(value: 30))

VTCompressionSessionPrepareToEncodeFrames(session!)
```

**使用场景**：
- 视频录制时的实时硬件编码
- 视频播放时的硬件解码（提高性能、降低功耗）
- 视频转码处理
- 低延迟视频会议

**常见坑**：
1. **解码器初始化依赖 SPS/PPS**：解码器必须在拿到 SPS（序列参数集）和 PPS（图像参数集）数据后才能初始化
2. **硬件支持检查**：使用 `VTIsHardwareDecodeSupported` 检查设备是否支持特定编码格式的硬件解码
3. **内存管理**：CF 对象需要手动管理内存（`CFRelease`）
4. **编码参数**：不同设备支持的编码参数不同，需要做好降级处理


### 2.4 AudioToolbox — 音频工具箱

**定位**：提供录音、播放和流解析的接口。

**架构**：AudioToolbox 是 C 语言接口，偏向底层，提供应用层级的音频服务。它在 Core Audio 之上封装了更易用的 API。

**核心服务**：
| 服务                       | 说明                         |
| -------------------------- | ---------------------------- |
| Audio Queue Services       | 连接音频硬件，管理录音或播放 |
| Audio Services             | 播放短音效或触发振动         |
| Audio Converter Services   | 音频格式转换                 |
| Audio File Services        | 读写音频文件                 |
| Audio File Stream Services | 解析音频流                   |
| Audio Unit v3 Plug-Ins     | 自定义音频效果扩展           |

**设计模式**：
- **队列模式**：Audio Queue 管理音频数据的缓冲和传输
- **回调模式**：通过回调函数处理音频数据
- **插件架构**：Audio Unit v3 通过 App Extension 实现自定义音频处理

**工作流程**（音频播放）：
```
1. 创建 AudioQueue 实例
2. 设置音频格式（ASBD）
3. 分配缓冲区并加入队列
4. 实现播放回调（填充音频数据）
5. AudioQueueStart 开始播放
6. 在回调中持续填充缓冲区
7. AudioQueueStop 停止播放
8. 释放资源
```

**代码示例**（播放系统音效）：
```swift
import AudioToolbox

// 播放系统声音
func playSystemSound() {
    AudioServicesPlaySystemSound(1000)  // 振动
    // 或自定义音效
    guard let url = Bundle.main.url(forResource: "click", withExtension: "caf") else { return }
    var soundID: SystemSoundID = 0
    AudioServicesCreateSystemSoundID(url as CFURL, &soundID)
    AudioServicesPlaySystemSound(soundID)
    // 完成后释放
    AudioServicesDisposeSystemSoundID(soundID)
}
```

**使用场景**：
- 播放短音效（UI 交互反馈、通知声音）
- 在线流媒体音乐播放
- 音频格式转换
- 自定义音频播放器封装
- 音频会话管理（iOS 特有）

**常见坑**：
1. **Audio Queue 限制**：只能处理未压缩的 PCM 音频
2. **系统音效限制**：`AudioServicesPlaySystemSound` 只能播放 30 秒以内的音效
3. **格式支持**：Audio File Services 支持的格式有限，复杂格式需使用 Extended Audio File Services

### 2.6 SoundAnalysis — 声音分类

**定位**：通过分析音频文件或流来分类各种声音。

**架构**：SoundAnalysis 是高级框架，内部使用 Core ML 模型进行声音分类。所有计算都针对硬件加速进行优化，并在设备本地完成。

**核心类**：
| 类                       | 说明                            |
| ------------------------ | ------------------------------- |
| `SNAudioFileAnalyzer`    | 对音频文件运行声音分类请求      |
| `SNAudioStreamAnalyzer`  | 分析音频数据流（如麦克风输入）  |
| `SNClassifySoundRequest` | 使用 Core ML 模型分类声音的请求 |
| `SNClassificationResult` | 包含分类结果                    |

**设计模式**：
- **请求-响应模式**：创建请求（Request）→ 提交给分析器 → 获取结果（Result）
- **策略模式**：可使用内置分类器（300+ 种声音）或自定义 Core ML 模型

**工作流程**（实时声音分类）：
```
1. 创建 SNAudioStreamAnalyzer
2. 创建 SNClassifySoundRequest（使用内置或自定义模型）
3. 将请求添加到分析器
4. 从麦克风获取音频数据（AVAudioEngine + AVAudioInputNode）
5. 将音频缓冲提交给分析器（analyzer.analyze(buffer, completionHandler:)）
6. 在完成回调中获取 SNClassificationResult
7. 处理分类结果（最高置信度的声音类别）
```

**代码示例**（内置声音分类）：
```swift
import SoundAnalysis
import AVFoundation

class SoundClassifier {
    private var analyzer: SNAudioStreamAnalyzer?
    private let audioEngine = AVAudioEngine()
    
    func startClassification() throws {
        // 1. 创建分析器
        analyzer = SNAudioStreamAnalyzer()
        
        // 2. 创建请求（使用内置分类器）
        let request = try SNClassifySoundRequest(classifierIdentifier: .version1)
        try analyzer?.add(request, withObserver: self)
        
        // 3. 配置音频输入
        let inputNode = audioEngine.inputNode
        let format = inputNode.outputFormat(forBus: 0)
        
        // 4. 安装音频监听
        inputNode.installTap(onBus: 0, bufferSize: 4096, format: format) { buffer, time in
            try? self.analyzer?.analyze(buffer, atAudioFramePosition: time.sampleTime)
        }
        
        // 5. 启动音频引擎
        audioEngine.prepare()
        try audioEngine.start()
    }
}

extension SoundClassifier: SNResultsObserving {
    func request(_ request: SNRequest, didProduce result: SNResult) {
        guard let result = result as? SNClassificationResult else { return }
        let top = result.classifications.first
        print("识别到声音: \(top?.identifier ?? "未知") 置信度: \(top?.confidence ?? 0)")
    }
}
```

**使用场景**：
- 识别环境声音（笑声、掌声、警笛、狗叫等）
- 音乐流派分类
- 语音/音乐/静音检测
- 智能音频索引
- 内容审核

**常见坑**：
1. **权限**：使用麦克风需要 `NSMicrophoneUsageDescription` 权限
2. **音频格式**：确保提交给分析器的音频格式被支持
3. **性能**：实时分析时注意 buffer 大小和频率，避免 CPU 过载
4. **模型版本**：内置分类器 `version1` 可识别约 300 种日常声音

### 2.8 Speech — 语音识别

**定位**：提供语音识别功能，支持设备端处理。

**架构**：Speech 框架集成了声学模型、语言模型和端到端深度学习算法。支持**混合识别模式**：在线模式通过神经网络模型在云端处理，离线模式依赖设备端轻量级模型。

**核心类**：
| 类                                      | 说明                       |
| --------------------------------------- | -------------------------- |
| `SFSpeechRecognizer`                    | 语音识别器（支持指定语言） |
| `SFSpeechAudioBufferRecognitionRequest` | 音频流识别请求             |
| `SFSpeechRecognitionResult`             | 识别结果                   |
| `SFSpeechRecognitionTask`               | 识别任务（可取消）         |

**设计模式**：
- **请求-任务模式**：创建请求 → 提交识别 → 获取任务 → 监听结果
- **委托模式**：通过 `SFSpeechRecognitionTaskDelegate` 接收识别结果

**工作流程**（实时语音识别）：
```
1. 检查 SFSpeechRecognizer.authorizationStatus()
2. 请求语音识别授权
3. 创建 SFSpeechRecognizer（指定语言）
4. 创建 SFSpeechAudioBufferRecognitionRequest
5. 从 AVAudioEngine 获取音频缓冲
6. 提交识别请求，获取 SFSpeechRecognitionTask
7. 在委托方法中接收识别结果
8. 处理识别文本
```

**代码示例**：
```swift
import Speech

class SpeechRecognizer: NSObject {
    private let recognizer = SFSpeechRecognizer(locale: Locale(identifier: "zh-CN"))
    private var recognitionRequest: SFSpeechAudioBufferRecognitionRequest?
    private var recognitionTask: SFSpeechRecognitionTask?
    private let audioEngine = AVAudioEngine()
    
    func startRecording() throws {
        // 检查权限
        guard SFSpeechRecognizer.authorizationStatus() == .authorized else {
            throw NSError(domain: "Speech", code: -1)
        }
        
        // 取消之前的任务
        recognitionTask?.cancel()
        recognitionTask = nil
        
        // 创建请求
        recognitionRequest = SFSpeechAudioBufferRecognitionRequest()
        recognitionRequest?.shouldReportPartialResults = true
        
        // 配置音频输入
        let inputNode = audioEngine.inputNode
        let format = inputNode.outputFormat(forBus: 0)
        inputNode.installTap(onBus: 0, bufferSize: 1024, format: format) { buffer, _ in
            self.recognitionRequest?.append(buffer)
        }
        
        // 提交识别
        recognitionTask = recognizer?.recognitionTask(with: recognitionRequest!) { result, error in
            if let result = result {
                print("识别文本: \(result.bestTranscription.formattedString)")
            }
            if error != nil {
                self.audioEngine.stop()
                inputNode.removeTap(onBus: 0)
            }
        }
        
        audioEngine.prepare()
        try audioEngine.start()
    }
}
```

**使用场景**：
- 语音输入（键盘听写替代）
- 实时翻译
- 语音控制
- 语音备忘录转文字

**常见坑**：
1. **权限**：需要 `NSSpeechRecognitionUsageDescription` 和麦克风权限
2. **设备支持**：`SFSpeechRecognizer.supportsOnDeviceRecognition` 检查离线支持
3. **网络依赖**：在线模式需要网络连接
4. **语言支持**：不同语言识别精度不同

### 3.4 层级选择原则

**原则 1：尽可能使用高层框架**

高层框架（AVFoundation、MusicKit）更易用、代码更少、更安全。只有在高层框架无法满足需求时才向下层迁移。

**原则 2：根据延迟需求选择**

| 延迟要求         | 框架选择                 |
| ---------------- | ------------------------ |
| 宽松（>100ms）   | AVFoundation             |
| 中等（10-100ms） | AudioToolbox             |
| 严格（<10ms）    | Core Audio (Audio Units) |

**原则 3：根据控制粒度选择**

- **高层**：AVFoundation — 声明式、易用、功能完整
- **中层**：AudioToolbox、VideoToolbox — C 接口、更细粒度控制
- **底层**：Core Audio、Core Media — 最大灵活性、最大复杂度


## 四、常见跨框架坑

### 4.1 时间表示不一致

**坑**：不同框架使用不同的时间表示方式（NSTimeInterval vs CMTime）。

**解决**：统一使用 `CMTime`，需要时通过 `CMTimeGetSeconds` 转换为 Double。

### 4.2 音频会话冲突

**坑**：多个框架同时使用音频时（如 AVFoundation 和 Core Audio）产生冲突。

**解决**：使用 `AVAudioSession` 统一管理音频会话，设置合适的 category 和 options。

### 4.3 权限重复请求

**坑**：不同框架需要不同权限（相机、麦克风、语音识别、Apple Music），权限描述不完整导致审核被拒。

**解决**：在 Info.plist 中完整配置所有需要的权限描述。

### 4.4 性能叠加

**坑**：同时使用多个框架（如 VideoToolbox 硬编 + Core Audio 处理）导致 CPU/GPU 过载。

**解决**：监控性能指标，必要时降低分辨率、帧率或采样率。

### 4.5 框架版本兼容性

**坑**：不同 iOS 版本对框架的支持不同（如 SoundAnalysis 需要 iOS 13+，MusicKit 需要 iOS 15+）。

**解决**：使用 `@available` 检查，为低版本提供降级方案。
