# L2CAP简介

## 一、专业术语
**全称：Logical Link Control and Adaptation Protocol 逻辑链路控制与适配协议**,是蓝牙BR/EDR、BLE两套协议栈共用**中层调度适配器**，架在基带/链路层之上、ATT/RFCOMM/SDP等上层协议之下，统一封装无线数据包，完成多路分流、分片重组、流量管控，屏蔽底层射频复杂细节。

## 二、核心功能
1. **Logical Link 逻辑链路**
底层基带/LL只负责一条真实无线电磁波物理链路；L2CAP在这条物理链路上虚拟出多条互不干扰的**独立逻辑通道**。
例：耳机同时走音频流、按键上报、电量读取三条数据，靠不同逻辑通道隔离，不会互相堵塞。
区分：BLE底层LL（链路层）≠中层L2CAP，LL只处理空口无线时序，L2CAP处理上层业务数据包分发。

2. **Control 链路控制**
提供全链路管理能力：逻辑通道创建/销毁、收发流量管控、丢包重传、传输时序调度。

3. **Adaptation 适配（核心精髓）**
上下层数据格式、包大小不匹配，全部由L2CAP做“翻译缓冲适配”：
上层应用大数据 → 自动分片，拆成基带支持的小包空中传输；
空中零散分片到达 → 自动重组完整数据包交给上层；
统一封装数据包头部，上层协议不用关心底层射频限制。

## 三、协议栈层级（上下层关系）
### 完整分层结构（BR/EDR & BLE通用分层逻辑）
```
应用层配置文件（A2DP/HFP/GATT/SPP）
        ↓
上层业务协议（ATT/SDP/RFCOMM）
        ↓
✅ L2CAP 逻辑链路控制适配层（核心中转层）
        ↓
HCI 主机控制器接口
        ↓
基带Baseband / BLE LL链路层
        ↓
2.4GHz射频RF空中接口
```
### 关键区分
经典BR、低BLE都存在L2CAP，但两套规范、数据包格式、支持能力完全独立，**无法互通**：
- BR-L2：适配RFCOMM串口、A2DP音频，原生流式传输；
- BLE-L2：基础固定通道承载GATT，v4.2新增CoC高速流式通道。

## 四、三大核心基础功能（对应名称三段释义）
### 1. 逻辑信道多路复用（Logical Link）
单条蓝牙物理连接，依靠 **CID 通道标识符** 区分多条独立数据流，实现多业务并发传输。
同一连接下，音频、串口、设备查询数据分流互不干扰。
#### BLE标准固定CID（硬件/协议内置，不可自定义）
| CID值  | 对应通道用途                            |
| ------ | --------------------------------------- |
| 0x0004 | ATT通道（GATT读写、通知全部走这里）     |
| 0x0005 | L2CAP信令通道（创建/销毁CoC、参数配置） |
| 0x0006 | SMP安全通道（配对、密钥交换）           |
动态CID（0x0040~0x007F）：CoC自定义通道建连时动态分配。

### 2. 分片与重组（Adaptation 核心适配能力）
底层无线基带PDU长度存在硬性上限，上层业务数据包大小不固定：
发送侧：L2CAP自动把超大SDU（上层数据单元）切分成多个PDU小包空中发送；
接收侧：收到零散分片后自动拼接还原完整数据，上层完全感知不到分片逻辑。

### 3. 链路控制（Control）
包含流量控制、丢包重传、通道生命周期管理：
1. 流量控制：防止发送方发包过快溢出设备缓冲区；
2. 重传机制：区分可靠传输/实时无重传两种模式；
3. 通道管理：建立、断开、修改通道参数（MTU、信用值）。

## 五、形象快递比喻（快速理解记忆）
把整套蓝牙通信比作物流运输系统：
1. 射频+基带 = 公路、货车（真实物理运输通道，只能装载固定尺寸纸箱）
2. **L2CAP = 物流中转分拣中心**
   - 适配：商家大件包裹拆成标准纸箱发货，到达后重新拼装；
   - 多路复用：分多条配送线路（CID区分不同业务）；
   - 链路控制：调度发货速度、丢件补发、开通/关闭配送线路。
3. 上层协议（GATT/RFCOMM）= 各个电商店铺（耳机、传感器、串口业务）

## 六、BR L2CAP 与 BLE L2CAP 核心差异
### 1 经典蓝牙 BR-L2CAP
1. 承载上层：RFCOMM(SPP串口)、A2DP、HFP、SDP；
2. 传输模型：原生字节流式，无20字节单包限制；
3. 通道类型：无连接广播通道、面向连接数据流通道；
4. 短板：无信用流控，大数据易缓冲区溢出；
5. iOS限制：基于BR的RFCOMM串口必须MFi认证才可连接。

### 2 BLE L2CAP（分两类通道，开发重点）
#### 类型1：固定基础通道（0x0004/0x0006）
所有普通GATT读写、通知、配对默认使用，缺点：
- ATT通道默认MTU仅23字节，扣除头部有效载荷仅20字节；
- 报文式交互，非连续数据流，大批量数据容易阻塞；
- 老旧BLE4.0芯片全部支持。

#### 类型2：L2CAP CoC 信用式面向连接通道（v4.2新增，重点）
##### 1）核心概念
CoC = LE Credit Based Connection Oriented Channel，基于信用流控的自定义逻辑通道，**完全绕过ATT/GATT层**。
##### 2 关键参数
- PSM：自定义通道端口号，主从设备约定相同PSM即可建立独立通道；
- MTU最大支持65535字节（64KB），无20字节限制；
- Credit信用机制：接收方预先分配可发包额度，信用耗尽自动暂停发送，天然防溢出。
##### 3 核心优势
1. 纯流式二进制传输，使用体验接近传统SPP串口；
2. 独立逻辑通道，GATT读写、控制指令不会被大数据阻塞；
3. 无需频繁分包，OTA、高速传感器吞吐量大幅提升；
4. iOS原生CoreBluetooth直接支持，无需MFi硬件认证。
##### 4 适用场景
固件OTA升级、车载实时控制、高速日志采集、音频数据流；
##### 5 短板
仅BLE4.2及以上芯片硬件支持，低成本BLE4.0模组不兼容。

## 七、关键专业名词通俗释义
1. **CID（Channel ID 通道ID）**
逻辑通道唯一标识，数据包头部自带标签，L2CAP依靠CID分流到对应上层协议。分固定系统CID、动态CoC通道CID。
2. **PSM（协议复用标识）**
仅CoC通道使用，相当于自定义端口，主从约定一致PSM才能建立专属高速通道。
3. **MTU 最大传输单元**
单条L2通道单次能承载最大数据长度：
- GATT固定通道：默认23字节；
- CoC通道：最高64KB；
4. **SDU / PDU**
- SDU：上层交给L2CAP的原始业务数据；
- PDU：L2CAP添加头部、分片后，发给底层的空中数据包。

## 八、L2CAP PDU基础数据包结构
BLE标准L2CAP基础帧（B-Frame）固定4字节头部 + 可变负载
```
| 长度(2字节) | CID通道ID(2字节) | 上层数据负载 |
```
- 长度：仅代表后面负载字节数，不含头部；
- CID：分流标签，区分ATT/SMP/自定义CoC；
- 负载：完整ATT报文、CoC数据流等上层原始数据。

## 九、开发核心对比：GATT固定通道 VS L2CAP CoC
| 对比维度 | GATT ATT固定L2通道                       | L2CAP CoC自定义通道    |
| -------- | ---------------------------------------- | ---------------------- |
| 协议层级 | 依赖ATT/GATT协议封装                     | 直接L2CAP层，跳过ATT   |
| 单包上限 | 默认20字节有效载荷                       | 最高64KB，无需频繁分包 |
| 数据模型 | 离散报文读写（Read/Notify）              | 连续二进制字节流       |
| 队列阻塞 | 所有数据共用一条通道，大数据会卡控制指令 | 独立通道，互不抢占资源 |
| 开发逻辑 | 需定义服务、特征、CCCD通知               | 类似传统串口流式收发   |
| 硬件要求 | BLE4.0全兼容                             | BLE4.2及以上芯片       |
| iOS使用  | 原生无认证可用                           | 原生无认证可用         |

## 十、L2CAP与RFCOMM区分
1. L2CAP：中层通用适配层，BR、BLE两套蓝牙都存在，是底层基础调度；
2. RFCOMM：**仅经典BR专属上层协议**，运行在BR-L2CAP之上，用于虚拟串口多路复用；
3. BLE协议栈不存在RFCOMM，无法直接运行RFCOMM；
4 硬件限制：RFCOMM串口设备iOS必须MFi；BLE CoC通道免认证，是iOS串口方案最优解。

## 十一、结
L2CAP是蓝牙上下层之间的调度适配中转层，依托物理无线链路虚拟多条独立逻辑通道；
依靠CID完成数据多路分流，自动分片重组适配底层包长限制，配套流量与重传管控；
经典蓝牙L2CAP承载RFCOMM串口、音频；BLE分为GATT固定短通道与CoC高速流式通道；
开发高速、低延迟蓝牙通信优先选用BLE L2CAP CoC，规避GATT 20字节限制与MFi认证成本。
