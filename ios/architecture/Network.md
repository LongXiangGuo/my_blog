# 移动端通用网络层封装思路

## 第一部分：设计理念与顶层战略（顶层大纲）

### 1.1 核心设计目标
- **高可用**：任何网络故障不能导致App核心功能不可用。
- **高性能**：弱网环境下依然保持可接受的加载速度。
- **可观测**：全链路可监控、可诊断、可回溯。
- **可容灾**：多级降级机制，确保极端情况下的基本可用。
- **业务无感**：上层业务不需要关心协议转发、超时降级等复杂逻辑（借鉴MobileSDN理念）。

### 1.2 整体分层架构（五层标准）
1. **业务应用层**：Swift/OC ViewController、Widget、Extension。
2. **外层能力层**：业务增强（预请求、请求合并、离线队列、灰度域名、弱网策略、熔断降级）。
3. **NetworkCore 核心门面层**：统一入口、OC/Swift双接口、全局HTTP配置、拦截器流水线、三层缓存管理。
4. **Alamofire 底层传输引擎层**：并发调度池、连接池、DNS解析器、SSL校验、流量压缩、分级超时。
5. **底层系统层**：URLSession / CFNetwork / Network.framework。


## 第二部分：核心基础能力层（Foundation）

### 2.1 DNS解析与调度优化
- **HTTPDNS优先策略**：
    - 使用阿里云/腾讯云HTTPDNS SDK，基于DoH（DNS over HTTPS）加密解析，防运营商劫持。
    - 技术实现：iOS 14+ 使用 `network.framework` 的 `nw_resolver_config_create_https` 应用级配置；兼容方案使用SDK内置解析器。
- **多级DNS缓存机制**：
    - L1：内存LRU缓存（App运行期，毫秒级响应）。
    - L2：磁盘加密持久化缓存（App重启复用）。
    - L3：HTTPDNS服务端实时解析。
    - L4：LocalDNS（系统兜底）。
    - L5：硬编码Backup IP（极端容灾）。
- **动态域名与灰度切流**：
    - 支持主备域名故障自动切换（5次失败触发熔断）。
    - 支持后台远程配置灰度流量比例（10%新域名验证）。
    - 域名收敛：客户端单域名收编，SLB层还原，提升连接复用率。

### 2.2 连接管理层（Connection Management）
- **连接池复用**：基于Alamofire/URLSession的`httpMaximumConnectionsPerHost`控制，保持长连接，消除频繁TCP/TLS握手。
- **长连接通道（心跳保活）**：
    - 自适应心跳算法：成功则逐步延长间隔（最大5分钟），失败则缩短并触发重连。
    - 支持NAT超时穿透与网络切换（Wi-Fi <-> 4G）连接迁移。
- **多网协同**：Wi-Fi与蜂窝网络多路复用，弱网下自动切换最优链路。


## 第三部分：传输协议与性能优化（Performance & Protocol）

### 3.1 多协议融合栈
- **HTTP/1.1**：降级兜底（兼容性最好）。
- **HTTP/2**：常规业务，多路复用、头部压缩（默认启用）。
- **HTTP/3 (QUIC)**：弱网/视频场景。
    - 技术选型：Google Cronet（iOS/Android）或自研XQUIC。
    - 核心优势：0-RTT建连、无队头阻塞、连接迁移。
    - 自动降级策略：QUIC失败 → HTTP/2 → HTTP/1.1。

### 3.2 并发线程调度池（防雪崩）
- **分层优先级调度**（Swift Concurrency Task托管）：
    - **高优池（并发4~6）**：首页、支付、核心信息。
    - **普通池（并发10）**：列表、详情。
    - **低优池（并发2~4）**：埋点、日志、预加载。
- **请求去重（Deduplication）**：1秒内相同URL+参数复用同一个Task，不重复发起网络。

### 3.3 极致性能微优化
- **启动预热**：App冷启动时异步预建核心域名连接（TCP+TLS预热）。
- **请求合并/批处理**：高频埋点攒批（50条/2秒）统一上报；页面多接口自动合并为Batch请求。
- **流量压缩**：弱网自动开启GZIP/Brotli压缩，传输体积降低60%。
- **分级动态超时**：Wi-Fi总超时15s，4G/5G 20s，弱网2G 30s（连接/读取双阈值分离）。


## 第四部分：弱网全链路优化（Weak Network Strategy）

### 4.1 网络状态分级检测
- **五级分类**：Wi-Fi满格、4G/5G良好、弱网（高延迟>800ms/丢包>10%）、无网、VPN/代理。
- **自适应策略引擎**：
    - **智能重试退避**：指数退避（1s→2s→4s），最多3次；幂等校验（POST支付/提交类禁止自动重试）。
    - **降帧/降数据**：弱网下列表接口自动追加 `pageSize=10`（正常20），减少下行数据。
    - **分片上传/断点续传**：大文件切分为256KB分片，失败仅重传失败分片。

### 4.2 离线持久化队列
- 无网时用户操作（表单、点赞、评论）写入沙盒持久化队列（CoreData/JSON文件）。
- 网络恢复后按优先级自动补发，支持去重防重复提交。


## 第五部分：三层加密缓存架构（Cache System）——深度落地细则

### 5.1 分层定位与核心规则总表
| 层级                   | 介质            | 加密规则               | 准入标准（必须满足）                                 | 淘汰策略                                                | 适用场景                                    |
| :--------------------- | :-------------- | :--------------------- | :--------------------------------------------------- | :------------------------------------------------------ | :------------------------------------------ |
| **一级：内存LRU**      | App内存         | **明文**（进程隔离）   | 访问频次≥3次/会话；TTL≤1小时；**Data<200KB**。       | 最大100条；内存警告清空50%；LRU访问时间淘汰。           | 首页Tab、高频配置、短时效接口。             |
| **二级：系统URLCache** | 系统缓存目录    | **明文**（仅静态资源） | 仅**GET**方法；服务端支持Cache-Control；无隐私数据。 | 系统自动（配额LRU）。                                   | 图片、图标、静态JS/CSS（服务端304协商）。   |
| **三级：加密磁盘**     | 沙盒Cache文件夹 | **强制AES-256-GCM**    | TTL≥30分钟；离线兜底需求；隐私敏感数据。             | 总容量200MB；超限按`lastAccessTime`删除文件；登出全清。 | 历史订单、收藏、7天长期字典、弱网兜底数据。 |

### 5.2 读写链路细化（代码级逻辑）
- **读取链路**（优先级递减）：内存 → 三级加密磁盘（离线可返回过期） → 二级系统缓存 → **发起网络请求**。
- **写入链路**：
    - 网络请求成功 → 校验准入标准 → 写入内存（如符合） + 强制写入三级加密磁盘（如开启缓存）。
    - **二级系统缓存**：仅由Alamofire/URLSession的`CachedResponseHandler`自动拦截存储（业务加密数据被拦截禁止存入）。
- **核心技术决策**：三级磁盘**使用独立加密文件（MD5 Key 命名）而非SQLite**，原因是KV查询文件寻址更快、切换用户清空只需删除文件夹（无碎片）、零依赖。

### 5.3 安全保障（Security）
- **传输层**：SSL Pinning（公钥固定）+ 强制TLS 1.2/1.3。
- **数据层**：RSA交换AES密钥，Body全量加密；请求签名（防篡改/重放）。
- **缓存安全**：内存敏感数据页面`deinit`主动清除；磁盘全量AES-256加密；用户登出自动清空三级缓存。


## 第六部分：容灾、熔断与可靠性（Resilience）

### 6.1 多级容灾降级矩阵
- **L1 协议降级**：HTTP/3失败 → HTTP/2 → HTTP/1.1。
- **L2 DNS降级**：HTTPDNS不可用 → LocalDNS → Backup IP硬直达。
- **L3 节点降级**：主域名连续5次失败 → 自动熔断切备用域名（后台异步探测恢复）。
- **L4 业务降级**：网络全不可用 → 返回离线缓存 + 提示“展示历史数据”。

### 6.2 熔断器模式（Circuit Breaker）
- 单一接口短时间失败率超30% → 熔断开启（5s内直接抛异常，不发起请求） → 半开状态探测恢复。


## 第七部分：全链路可观测性（Observability）

### 7.1 端到端监控指标
- **全阶段耗时采集**：DNS解析、TCP握手、TLS握手、首包（TTFB）、总耗时（通过`URLSessionTaskMetrics`/Alamofire `EventMonitor` 精准获取）。
- **多维度埋点**：按用户、地区、运营商、网络类型统计失败率与耗时分布。

### 7.2 日志与诊断
- **分级日志**：Debug环境全量明文打印；生产环境自动脱敏（手机号/身份证），仅打印关键头与状态码。
- **弱网诊断**：被动采集全部请求，精准识别弱网用户，辅助运营调整策略。


## 第八部分：全局配置与多环境（Configuration & Env）

- **全局HTTP统一配置**：集中管理BaseURL、全局Headers（设备/版本/Token）、超时默认值、SSL证书。
- **多环境隔离**：开发/测试/预发/生产，一键切换，且**不同环境缓存完全隔离**（防止测试数据污染生产）。
- **可自定义序列化/反序列化**：协议化`RequestEncoder`和`ResponseDecoder`，内置JSON/Form/Protobuf，业务可自定义加密解析器并自动处理全局错误码（401刷新Token、403风控）。


## 第九部分：Alamofire + Swift Concurrency 具体技术实现汇总

### 9.1 底层引擎集成
- 使用 `AF.request(...).serializingDecodable()` 原生支持 `async/await`。
- 利用 `async let` 实现多接口并行请求（减少等待时间）。
- `Session` 单例配置 `ServerTrustManager`（证书固定）和 `CachedResponseHandler`（系统缓存隔离）。

### 9.2 拦截器流水线（Interceptor Pipeline）
构建完整责任链（按顺序执行）：
1. `DNSInterceptor`（域名动态切换/灰度）。
2. `MetricsInterceptor`（开始计时）。
3. `EncryptionInterceptor`（请求体加密/签名）。
4. `CacheInterceptor`（读取三层缓存命中判断）。
5. `RetryInterceptor`（智能指数退避重试）。
6. `CacheWriteInterceptor`（响应成功后异步写入三层缓存）。

### 9.3 线程安全与生命周期
- **Actor 隔离**：`MemoryLRUCache`、`EncryptedDiskCache`、`PriorityDispatcher` 均使用 `actor` 保证数据竞争安全。
- **请求取消**：页面销毁时通过 `RequestLifecycleManager` 自动取消该页面所有进行中的请求（`onDisappear` 触发），避免内存泄漏与崩溃。


## 第十部分：辅助能力与边缘场景（Edge Cases）

- **Widget/Extension 兼容**：共享主Engine，独立小容量缓存路径，超时时间缩短至10s。
- **多文件下载管理器**：独立于业务缓存，支持暂停、断点续传、MD5校验、后台下载。
- **流量统计**：自动统计上行/下行流量，大文件下载前弹窗提醒用户。
- **App增量升级**：大安装包分片下载，弱网限速策略，不抢占业务带宽。


## 总结：架构核心优势

1. **分层解耦**：业务层只依赖 `NetworkCore` 门面，底层切换URLSession/Socket对上层透明。
2. **防御式编程**：DNS、缓存、弱网策略、熔断器各模块独立，**单模块故障不影响整体**（支持降级关闭）。
3. **数据驱动优化**：全链路监控闭环，所有阈值（超时/并发数/缓存大小/熔断比例）支持**后台远程动态下发**，无需发版即可调优。
4. **安全合规**：传输加密 + 缓存加密 + 数据脱敏，满足金融/电商级隐私合规要求。

本方案完整覆盖了弱网、安全、缓存、容灾、监控所有死角，使用于移动端网络基础设施,根据项目复杂度和具体业务需求可酌情删减部分功能。
