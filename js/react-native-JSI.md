## 一、架构概览

### 1.1 旧架构的痛点

在深入新架构之前，必须理解旧架构（Legacy Architecture）的根本缺陷：

```
┌─────────────────────────────────────────────────────────────────┐
│                    旧架构 (Bridge-based)                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌──────────────┐    JSON     ┌──────────────┐               │
│  │  JS 线程     │ ──────────► │  Bridge      │ ──────────►   │
│  │  (JSC/Hermes)│  序列化     │  (消息队列)   │   反序列化    │
│  └──────────────┘             └──────────────┘               │
│         ▲                            │                        │
│         │                            ▼                        │
│         │                     ┌──────────────┐               │
│         │                     │  Shadow 线程 │               │
│         │                     │  (Yoga布局)   │               │
│         │                     └──────────────┘               │
│         │                            │                        │
│         └────────────────────────────┘                        │
│              异步回调 (又一个来回)                              │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

**五大核心缺陷**：

| #    | 缺陷           | 影响                                                  |
| :--- | :------------- | :---------------------------------------------------- |
| 1    | **异步通信**   | 所有 JS↔Native 调用必须异步，无法同步返回             |
| 2    | **序列化开销** | 每次调用需 JSON 序列化/反序列化，消耗 CPU             |
| 3    | **启动缓慢**   | 所有 Native Modules 启动时全部加载                    |
| 4    | **单线程瓶颈** | JS 线程与 UI 线程严格分离，布局计算在独立 Shadow 线程 |
| 5    | **类型不安全** | 运行时反射推断类型，错误只能在运行时发现              |

### 1.2 新架构全景

新架构通过三个核心支柱解决上述问题：

```
┌─────────────────────────────────────────────────────────────────┐
│                  新架构 (New Architecture)                      │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │                  JavaScript 层                          │   │
│  │  - React 18+ 并发特性                                   │   │
│  │  - 动态 import / 代码拆分                               │   │
│  └─────────────────────────────────────────────────────────┘   │
│                              │                                  │
│                              ▼ (JSI 直接调用)                  │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │                    C++ 核心层                           │   │
│  │  ┌───────────────┐  ┌───────────────┐                 │   │
│  │  │  JSI 抽象层   │  │  TurboModules │                 │   │
│  │  │  (引擎适配)   │  │  (懒加载)     │                 │   │
│  │  └───────────────┘  └───────────────┘                 │   │
│  │  ┌───────────────┐  ┌───────────────┐                 │   │
│  │  │  Fabric       │  │  Yoga         │                 │   │
│  │  │  (渲染引擎)   │  │  (布局引擎)   │                 │   │
│  │  └───────────────┘  └───────────────┘                 │   │
│  └─────────────────────────────────────────────────────────┘   │
│                              │                                  │
│                              ▼                                  │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │              平台层 (iOS / Android)                     │   │
│  │  - 原生 View 创建与更新                                  │   │
│  │  - 事件处理                                             │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

**三大支柱**：

| 支柱             | 作用                         | 关键特性                              |
| :--------------- | :--------------------------- | :------------------------------------ |
| **JSI**          | JS 引擎与 C++ 之间的抽象接口 | 零拷贝、同步调用、引擎无关            |
| **TurboModules** | 原生模块系统                 | 懒加载、类型安全 (Codegen)            |
| **Fabric**       | 渲染引擎                     | 不可变 ShadowTree、并发渲染、同步布局 |


## 二、JSI：新架构的基石

### 2.1 设计哲学

JSI（JavaScript Interface）不是通信协议，而是一套 **C++ 层的抽象接口**，目标是建立一层**引擎无关的通用适配层**。

三个核心设计目标：

1. **去 Bridge**：消除异步消息队列和 JSON 序列化
2. **直接互操作**：JS 与 C++ 能直接共享对象和函数调用
3. **引擎无关**：同一套 API 可适配 Hermes、V8、JSC 等不同引擎

**核心洞察**：JSI 的本质是将 JS 引擎的 C++ Embedding API 抽象为一套统一接口。

### 2.2 三层架构

```
┌─────────────────────────────────────────────────────────────────┐
│                      JSI 三层架构                               │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  应用层 (Application Layer)                             │   │
│  │  - TurboModules / Fabric 的具体绑定                     │   │
│  │  - 往 Runtime 中注入具体的 JS 对象和函数                 │   │
│  └─────────────────────────────────────────────────────────┘   │
│                              │                                  │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  服务层 (Service Layer)                                 │   │
│  │  - 协调需要"安装"到 Runtime 中的能力                     │   │
│  │  - 管理 Runtime 的生命周期                               │   │
│  └─────────────────────────────────────────────────────────┘   │
│                              │                                  │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  抽象层 (Abstraction Layer) - jsi.h                    │   │
│  │  - 定义 JS 引擎需要实现的一组接口                        │   │
│  │  - JS 值模型的 C++ 包装 (Value, Object, String)         │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 2.3 核心数据结构（源码级）

`jsi.h` 定义了以下核心类型：

```cpp
// 1. Runtime - 核心引擎接口
class Runtime {
  // 所有 JS 操作都必须通过 Runtime 实例执行
  virtual Value evaluateJavaScript(
    const std::shared_ptr<const PreparedJavaScript>& js, 
    const std::string& sourceURL
  ) = 0;
  virtual Object global() = 0;
  virtual Value createObject() = 0;
  // ... 数百个虚函数
};

// 2. Value - 顶层包装类（Discriminated Union）
class Value {
  // 可表示: null, undefined, boolean, number, symbol, string, object
};

// 3. Pointer - GC 管理对象的基类
class Pointer {
  // 堆中 JS 对象的引用，受 GC 管理
  // 所有派生类都是不可拷贝的（移动语义）
};

// 4. 引用类型（继承自 Pointer）
class PropNameID : public Pointer;  // 属性名标识符
class Symbol : public Pointer;       // JS Symbol
class String : public Pointer;       // JS String
class Object : public Pointer;       // JS Object
class Array : public Object;         // JS Array
class Function : public Object;      // JS Function
```

### 2.4 引擎适配层（适配器模式）

```cpp
// Hermes 适配器
class HermesRuntime : public jsi::Runtime {
  // 实现所有虚函数，底层调用 Hermes 的 C++ API
};

// JSC 适配器（iOS）
class JSCRuntime : public jsi::Runtime {
  // 实现所有虚函数，底层调用 JavaScriptCore 的 C++ API
};

// V8 适配器（社区实现）
class V8Runtime : public jsi::Runtime {
  // 实现所有虚函数，底层调用 V8 的 C++ API
};
```

**关键设计**：上层（TurboModules、Fabric）只依赖 `jsi::Runtime` 抽象接口，完全不关心底层是哪个引擎。


## 三、TurboModules：原生模块系统重构

### 3.1 设计目标

TurboModules 针对旧架构 Native Modules 的五个核心缺陷进行重构：

| #    | 旧架构缺陷              | TurboModules 解决方案                |
| :--- | :---------------------- | :----------------------------------- |
| 1    | 不支持懒加载            | 模块在首次 `import` 时初始化         |
| 2    | 类型检查困难            | Codegen 编译时生成类型安全的胶水代码 |
| 3    | 单例生命周期绑定 Bridge | 生命周期由 JSI Runtime 管理          |
| 4    | 运行时反射扫描          | 编译时 Codegen 生成注册代码          |
| 5    | 运行时反射推断          | 编译时 Codegen 生成类型推断代码      |

### 3.3 懒加载并发控制（源码级）

```cpp
class TurboModuleHolder {
 private:
  std::mutex mutex_;
  std::condition_variable cv_;
  std::shared_ptr<TurboModule> module_;
  bool isCreating_ = false;
  bool isDone_ = false;
  
 public:
  std::shared_ptr<TurboModule> getModule() {
    std::unique_lock<std::mutex> lock(mutex_);
    
    if (module_) return module_;
    
    while (isCreating_) {
      cv_.wait(lock);  // 等待其他线程完成创建
    }
    
    if (module_) return module_;
    
    isCreating_ = true;
    lock.unlock();
    
    auto module = createModule();  // 耗时操作
    
    lock.lock();
    module_ = std::move(module);
    isCreating_ = false;
    isDone_ = true;
    cv_.notify_all();  // 唤醒所有等待线程
    return module_;
  }
};
```

### 3.4 同步调用实现

```cpp
jsi::Value TurboModule::get(jsi::Runtime& rt, const jsi::PropNameID& name) {
  std::string methodName = name.utf8(rt);
  
  auto it = methodMap_.find(methodName);
  if (it == methodMap_.end()) {
    return jsi::Value::undefined();
  }
  
  // 返回 JS Function，调用时同步执行 Native 代码
  return jsi::Function::createFromHostFunction(
    rt, name, 0,
    [this, methodName](jsi::Runtime& rt, 
                        const jsi::Value& thisVal,
                        const jsi::Value* args, 
                        size_t count) -> jsi::Value {
      // JS 线程会阻塞等待 Native 返回
      return this->invokeMethod(rt, methodName, args, count);
    }
  );
}
```

### 4.2 三大阶段：Render → Commit → Mount

#### 阶段一：Render（渲染）- JS 线程

调用栈（初次渲染）：

```
ReactFabric.render()
  → updateContainer()
    → React Reconciler (render 阶段)
      → commit 阶段
        → UIManagerBinding.createNode()   ← JSI 调用
        → UIManagerBinding.appendChild()
        → UIManagerBinding.completeRoot()
```

关键操作：
- `createNode()`：在 C++ 堆上创建 `ShadowNode` 实例
- `cloneNode()`：更新时克隆现有节点（不可变）
- `appendChild()`：建立父子关系
- `completeRoot()`：完成整棵树，触发提交

#### 阶段二：Commit（提交）- 后台/UI 线程

ShadowTree 使用**乐观锁 CAS**完成提交：

```cpp
RootShadowNode::UniQue tryCommit(
    const ShadowNodeFamily& family,
    const RootShadowNode& oldRoot,
    const RootShadowNode& newRoot) {
  
  // 1. 执行 Yoga 布局计算
  newRoot.layoutIfNeeded();
  
  // 2. 乐观锁 CAS
  RootShadowNode* expected = const_cast<RootShadowNode*>(&oldRoot);
  if (atomic_compare_exchange_strong(&current_, &expected, &newRoot)) {
    // 3. 生成 Mutation 指令列表
    auto mutations = calculateMutations(oldRoot, newRoot);
    // 4. 推送给 MountingCoordinator
    mountingCoordinator_->pushTransaction(mutations);
  } else {
    // CAS 失败，有并发更新，重试
  }
}
```

**线程模型**：
- 默认在**后台线程**执行 Commit（不阻塞 UI）
- 高优先级事件可在 **UI 线程同步执行** Commit+Mount

#### 阶段三：Mount（挂载）- UI 线程

```cpp
class MountingCoordinator {
  std::queue<MountingTransaction> transactions_;
  
  void pushTransaction(MountingTransaction transaction) {
    transactions_.push(std::move(transaction));
    scheduleMount();  // 调度 UI 线程执行
  }
  
  void mount() {
    auto transaction = transactions_.pop();
    auto& mutations = transaction.getMutations();
    
    for (const auto& mutation : mutations) {
      switch (mutation.type) {
        case Create:   // 创建原生视图
        case Delete:   // 删除原生视图
        case Insert:   // 插入子视图
        case Update:   // 更新属性
        case Remove:   // 移除子视图
      }
    }
  }
};
```

### 4.3 不可变 ShadowNode（源码级）

```cpp
class ShadowNode {
 public:
  // 所有字段都是 const
  const ShadowNodeFamily& family_;      // 节点族（追踪谱系）
  const Props::Shared props_;           // 属性（共享指针，不可变）
  const State::Shared state_;           // 状态（共享指针，不可变）
  const ShadowNode::List children_;     // 子节点列表（不可变）
  
  // 克隆：产生新节点，共享未变化的子节点
  ShadowNode::Unshared clone(
      const Props::Shared& props,
      const ShadowNode::List& children) const {
    return std::make_shared<ShadowNode>(
      family_, 
      props ? props : props_, 
      state_,
      children ? children : children_
    );
  }
};
```

**不可变性的三大好处**：
1. **线程安全**：多线程可同时读取，无需加锁
2. **并发渲染**：React 18 的并发特性可安全中断和恢复
3. **高效 Diff**：通过指针比较快速判断节点是否变化

### 4.4 View Flattening（视图扁平化）

```cpp
bool ViewShadowNode::isLayoutOnly() const {
  // 判断该 View 是否"仅用于布局"
  // 如果是，该 View 可以被"扁平化"——不创建原生视图
  return !getProps()->backgroundColor.hasValue()
      && !getProps()->borderWidth.hasValue()
      && !getProps()->onClick
      // ... 更多条件
      ;
}
```

扁平化后，布局信息上浮到父节点，减少原生视图数量，提升渲染性能。

### 5.3 基于寄存器的字节码

Hermes 的字节码是**基于寄存器的**，与基于栈的字节码（如 JVM）不同：

```
// 基于寄存器的字节码示例
// JS 代码: let a = 1; let b = 2; let c = a + b;

// Hermes 字节码（概念）
LoadConst    R0, 1        // R0 = 1
LoadConst    R1, 2        // R1 = 2
Add          R2, R0, R1   // R2 = R0 + R1

// 对比：JVM 基于栈的字节码
iconst_1                 // 压栈 1
iconst_2                 // 压栈 2
iadd                     // 弹出2个，相加，压栈结果
istore_2                 // 弹出，存入局部变量
```

**基于寄存器的优势**：
- **更少的指令**：不需要频繁的 push/pop 操作
- **更快的执行**：操作数直接指向寄存器，减少内存访问
- **更小的字节码体积**：指令更紧凑

### 5.4 执行引擎（解释器核心）

```cpp
void interpret(CodeBlock* codeBlock) {
  uint32_t ip = 0;  // 指令指针
  PinnedHermesValue registers[codeBlock->getNumRegisters()];
  
  while (true) {
    uint8_t opcode = codeBlock->getOpcode(ip);
    ip++;
    
    switch (opcode) {
      case OP_LoadConst: {
        uint32_t reg = codeBlock->getOperand(ip); ip++;
        uint32_t constIdx = codeBlock->getOperand(ip); ip++;
        registers[reg] = codeBlock->getConstant(constIdx);
        break;
      }
      case OP_Add: {
        uint32_t dest = codeBlock->getOperand(ip); ip++;
        uint32_t src1 = codeBlock->getOperand(ip); ip++;
        uint32_t src2 = codeBlock->getOperand(ip); ip++;
        registers[dest] = registers[src1] + registers[src2];
        break;
      }
      case OP_Ret: {
        return;
      }
    }
  }
}
```

## 十一、最佳实践

### 11.1 新架构启用配置

```javascript
// metro.config.js
const { getDefaultConfig, mergeConfig } = require('@react-native/metro-config');

const config = {
  // 启用 Hermes 字节码预编译
  transformer: {
    getTransformOptions: () => ({
      transform: {
        // 内联 require 优化
        inlineRequires: true,
      },
    }),
  },
};

module.exports = mergeConfig(getDefaultConfig(__dirname), config);
```

### 11.2 自定义 TurboModule 示例

```typescript
// specs/NativeCalculator.ts
import type { TurboModule } from 'react-native';
import { TurboModuleRegistry } from 'react-native';

export interface Spec extends TurboModule {
  // 同步方法
  add(a: number, b: number): number;
  // 异步方法
  multiply(a: number, b: number): Promise<number>;
}

export default TurboModuleRegistry.getEnforcing<Spec>('Calculator');
```

### 11.3 性能优化建议

1. **启用 Hermes 并预编译字节码**
   ```bash
   # 构建时生成字节码
   npx react-native bundle --platform android --dev false --entry-file index.js --bundle-output index.android.bundle --minify false
   ```

2. **使用 Codegen 确保类型安全**
   - 所有自定义原生模块都应编写 TypeScript Spec
   - 启用 Codegen 生成跨平台胶水代码

3. **利用 Fabric 的并发渲染**
   - 使用 `startTransition` 标记低优先级更新
   - 使用 `useDeferredValue` 优化输入响应

4. **动画性能**
   - 优先使用 `react-native-reanimated`（Worklet 在 UI 线程执行）
   - 使用 `useNativeDriver: true`（当使用 Animated API 时）
   - 避免在动画循环中执行 JS 计算

### 11.4 常见陷阱与解决方案

| 问题                          | 解决方案                             |
| :---------------------------- | :----------------------------------- |
| 第三方库不兼容新架构          | 升级到支持新架构的版本，或寻找替代库 |
| 自定义 Native Module 类型错误 | 检查 Codegen 配置，确保 Spec 正确    |
| 布局计算异常                  | 检查是否使用了不支持的 CSS 属性      |
| 内存泄漏                      | 正确管理 JSI 引用，避免循环引用      |
| 调试困难                      | 使用 React Native DevTools 进行调试  |


## 十二、术语表

| 术语                              | 定义                                                 |
| :-------------------------------- | :--------------------------------------------------- |
| **JSI**                           | JavaScript Interface，JS 引擎与 C++ 之间的抽象接口层 |
| **Bridge**                        | 旧架构中的异步通信机制，使用 JSON 序列化传递消息     |
| **TurboModules**                  | 新架构中的原生模块系统，支持懒加载和同步调用         |
| **Fabric**                        | 新架构中的渲染引擎，支持并发渲染和同步布局           |
| **Codegen**                       | 编译时代码生成工具，从 TS Spec 生成跨平台胶水代码    |
| **ShadowNode**                    | 不可变的 C++ 节点，表示 React 组件的布局和属性信息   |
| **ShadowTree**                    | ShadowNode 的不可变树结构，是渲染的核心数据结构      |
| **Yoga**                          | C++ 实现的 Flexbox 布局引擎                          |
| **Mutation**                      | 对原生视图的操作指令（创建/插入/更新/删除）          |
| **Hermes**                        | Meta 专为 RN 优化的 JS 引擎，支持 AOT 预编译         |
| **HadesGC**                       | Hermes 的分代并发垃圾回收器                          |
| **Hidden Class**                  | Hermes 用于优化属性访问的内联缓存机制                |
| **Worklet**                       | Reanimated 中可在 UI 线程执行的 JS 代码片段          |
| **VSync**                         | 垂直同步信号，驱动屏幕刷新的时钟信号                 |
| **乐观锁 (Optimistic Locking)**   | 使用 CAS 操作实现无锁并发的技术                      |
| **不可变对象 (Immutable Object)** | 创建后不可修改的对象，修改产生新实例                 |
| **RAM Bundle**                    | Random Access Modules Bundle，支持按需加载模块       |
| **Fast Refresh**                  | RN 的热更新机制，保留组件状态                        |


## 总结

React Native 新架构的本质是一次**彻底的底层推倒重来**：

1. **JSI** 通过 C++ 抽象层实现了 JS 与 Native 的**零拷贝、同步通信**，消除了 Bridge 的所有性能瓶颈
2. **TurboModules** 通过**懒加载**和 **Codegen 类型安全**，解决了旧模块系统的启动延迟和运行时错误问题
3. **Fabric** 通过 **C++ 核心 + 不可变 ShadowTree**，实现了**可中断的并发渲染**和**同步布局**，将渲染管线完全纳入 VSync 调度
4. **Hermes** 通过 **AOT 预编译**和**基于寄存器的字节码**，让 JS 在移动设备上以**接近原生的速度**执行

这四者共同构成了一个**从 JS 引擎到屏幕像素的完整、高性能渲染管线**，其设计深度和工程复杂度，在整个移动开发领域都堪称典范。新架构不仅是性能的提升，更是一次开发范式的革新，为 React Native 未来的发展奠定了坚实的基础。
