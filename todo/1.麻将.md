
## ✅ 一、项目核心需求

### 🎯 主要功能目标：

1. **局域网联机对战（支持4人）**
   - 支持局域网内 IP 自动发现或手动输入
   - 双向通信协议：UDP/TCP 基础通信 + 本地缓存状态同步（避免丢包）
   - 非常规“四人局”，可以是 2P/3P/4P，但需支持观战模式（最大 4 人）——
**核心是“对战”+“观战”分离**

2. **麻将规则实现**
   - 模拟真实麻将牌型（广东/上海/日本等流派可选）
   - 支持“和”、“杠”、“碰”、“吃”、“断线”等操作
   - 基础牌型判断（如自摸、胡牌、听牌、平胡、十三幺等）——**需实现麻将算法
引擎**

3. **观战模式（最多4人）**
   - 观众角色：非玩家，只能看牌局变化
   - 仅限“旁观者”不可下注/出牌，可选“自动轮询刷新”或手动选择“跳过”
   - 支持不同观众角色（如AI旁观、真人观战）

4. **界面设计**
   - 基于 Flutter 的 Material UI + 自定义组件实现麻将牌面动画
   - 游戏信息面板（当前局数、分数、剩余时间、状态）
   - 联机玩家头像/昵称显示，支持个性化设置（如“初代目雀士”、“高山景行”）


5. **社交功能**
   - 支持多设备登录（但不允许多账户共享同一房间）
   - 信息同步：牌局状态、当前手牌、得分实时更新
   - 多语言/自定义主题支持

6. **系统兼容性与性能要求**
   - iOS / macOS 系统原生能力适配（SwiftUI 或 Flutter + native bridge）
   - 支持 Mac App Store 上架，iOS App Store 上传
   - 单机模式可运行（离线联机），支持局域网“内网穿透”或广播通信

## 🧱 二、技术架构规划

### ⚙️ 前端框架：

- **Flutter**：跨平台开发，支持 iOS/macOS + Web
  - 使用 `flutter_native_speech` / `flutter_webview_plus` 实现本地调用（如相
机、麦克风）
  - 可搭配 `Flutter Bloc` 或 `Riverpod` 进行状态管理（推荐）

### 🌐 后端通信：

- **局域网通信协议**：
   - 使用 `Socket` / `TCP` + JSON 基于 Flutter 的 `dart:io` 库
     > iOS/macOS 平台不支持直接 Socket，需借助 `native_bridge` 或 `Flutter 
Desktop App` 插件（如 `flutter_native_speech` 不行，推荐用 `dart:ffi` 调用系
统接口）
   - 可选方案：
     - 使用 **WebRTC** + 本地广播服务（适合多设备组网）
     - 使用 **Zeroconf / Bonjour / mDNS** 发现局域网内其他游戏终端
     - 使用 `Flutter for Mac/IOS` 内置的 `dart:io` 基础通信（不推荐用于高并
发）

- 数据结构：
  ```json
  {
    "room_id": "abc123",
    "players": [
      { "id": "user0", "name": "范孝强", "role": "player" },
      { "id": "observer0", "name": "风花雪悦", "role": "observer" }
    ],
    "current_turn": "p1",
    "hand_cards": [ ... ] // 游戏牌堆
  }
  ```

### 📦 后端支持（可选）：

- 使用 **Dart + Flutter Server**（如 `server` 脚本）
   - 搭配 `dart:io` 进行 TCP/UDP Socket 通信
   - 多人并发时需实现“同步”机制（避免数据冲突）

### 🎨 界面设计：

- 使用 **Flutter Widget + 自定义动画组件** 实现麻将牌的动态效果
  > 可使用 `AnimatedBuilder` / `AnimatedContainer` + 状态管理实现“出牌+翻转
”动效

## 🧩 三、功能模块拆分

### 💡 模块一：游戏核心引擎（Game Engine）

1. **麻将规则引擎**  
   - 实现牌型判断（如是否为胡牌/自摸）
   - 支持“听牌”、“杠”、“碰”
   - 数据结构：`Map<String, List<Card>> hand_cards`

2. **游戏状态管理**
   ```dart
   class GameStore {
     final List<Player> players;
     int currentPlayerIndex; // 0~3 指定当前玩家
     bool isPlaying = false;

     void updatePlayerHand({required Map<int, List<Card>> hands}) {}
     void onPlayCard(int playerIdx, Card card) {}
   }
   ```

3. **牌局状态同步**（重要！）
   - 使用 `Bloc` / `Riverpod` 管理游戏状态
   - 数据变更时自动触发“广播”通知

---

### 💡 模块二：网络通信模块（Network）

1. **UDP/TCP 客户端**
   ```dart
   // Dart SDK 服务端通信示例
   void startGameServer() {
     var server = await Server.create();
     server.listen((connection) {
       connection.on('data', (message) {
         // 解析消息 -> 更新游戏状态
       });
     });
   }
   ```

2. **局域网广播发现**
   - 使用 `dart:io` 的 `DatagramSocket` + Bonjour / mDNS 发现服务端
   - 或使用 Flutter 插件：`flutter_bonjour`（支持 macOS/iOS）

3. **通信协议设计**  
   ```text
   Protocol:
   HEADERS: { "type": "game_start", "room_id": "...", "players": [...] }

   GAME_EVENT: { "action": "play_card", "card_idx": 0, "player_id": "p2" }
   ```

---

### 💡 模块三：UI/UX 设计

1. **游戏主界面**
   - 包含牌桌区域（中央）
   - 四个玩家头像 / 昵称 + 状态提示
   - 游戏状态提示区（是否轮到你？胡牌了？）

2. **观战界面**
   - 仅展示当前牌局状态，不提供交互按钮
   - 可设置“自动刷新”/“手动跳过”

3. **社交面板（可选）**
   - 显示玩家历史战绩、头像、成就徽章

---

### 💡 模块四：观战系统

1. **角色分离机制**
   - 游戏中只有 2~4 人“参与游戏”
   - 观众不参与牌局，但可看到“牌墙”、“状态栏”

2. **观战模式触发方式**
   - “邀请进入房间”按钮（仅限观察者）
   - 联机后自动检测是否有观众角色

## ⏳ 四、开发路径建议

### 🚀 阶段 1：基础功能搭建（3~4周）

- 完成 Flutter 项目初始化
- 实现游戏主界面 + 基础牌面结构
- 简单实现“四人联机”框架，支持 TCP 连接

> ✅ 目标：完成基本 UI 和玩家角色分发

### 🚀 阶段 2：麻将引擎开发（4~6周）

- 实现牌型判断逻辑（胡牌、听牌等）
- 完成出牌/吃/碰的交互处理
- 支持“自动翻转”动作动画（使用 `AnimatedBuilder` + `Opacity` 等）

> ✅ 目标：完成游戏核心玩法

### 🚀 阶段 3：网络通信模块（3~4周）

- 实现局域网广播发现机制
- 完成 TCP Socket 数据交换协议
- 使用 **WebSocket / Firebase** 等可选方案替代（如需更稳定）

> ✅ 目标：完成联机对战功能

### 🚀 阶段 4：观战系统与UI优化（2~3周）

- 实现“观战”模式界面
- 调试数据同步机制，避免卡顿/乱码问题
- 增加音效、背景音乐等增强体验

> ✅ 目标：完成完整功能 + 美化 UI

### 🚀 阶段 5：测试与发布（1~2周）

- 全面测试（Mac/iOS/Windows）
- 使用 Flutter DevTools 进行性能分析
- 提交 App Store / Mac App Store
