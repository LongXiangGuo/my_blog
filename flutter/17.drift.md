## Drift 架构设计与实现原理

### 架构分层

Drift 的架构可以清晰地分为三层：

```
┌─────────────────────────────────────────────────────┐
│                   应用层 (Your App)                   │
│      DAOs / 查询构建器 / 响应式Stream                 │
└─────────────────────────┬───────────────────────────┘
                          │
┌─────────────────────────▼───────────────────────────┐
│              Drift 核心层 (Type-safe ORM)            │
│  • 代码生成引擎 (build_runner)                       │
│  • 查询构建器 (DSL) / 验证SQL解析器                  │
│  • 响应式Stream管理                                  │
│  • 事务管理 (支持嵌套事务)               │
└─────────────────────────┬───────────────────────────┘
                          │
┌─────────────────────────▼───────────────────────────┐
│           QueryExecutor 抽象接口层                    │
│         (平台无关，支持多种后端实现)                   │
└─────────────────────────┬───────────────────────────┘
                          │
┌─────────────────────────▼───────────────────────────┐
│                 原生 SQLite 引擎                      │
│   NativeDatabase / WasmDatabase / SqfliteDatabase    │
└─────────────────────────────────────────────────────┘
```

### 实现原理

**1. 编译时类型安全（代码生成）**

Drift 的核心机制是基于 Dart 的 `build_runner` 进行编译时代码生成。开发者通过注解（如 `@DriftDatabase`、`@DriftAccessor`）和类定义来描述表结构，Drift 在编译阶段分析这些代码，自动生成所有 CRUD 操作的类型安全实现。

这意味着如果你在查询中拼错字段名，**编译时会直接报错**，而不是等到运行时崩溃。

**2. 两种查询方式**

- **Dart DSL 方式**：通过 Dart 代码构建查询，享受代码补全和类型检查
- **验证 SQL 方式**：将 SQL 写在 `.drift` 文件中，Drift 内置 SQL 解析器在编译时验证语法正确性，并生成对应的方法

**3. 响应式 Stream**

Drift 可以将任何查询转换为 `Stream`。当数据库数据发生变化时，所有订阅了该查询的 Stream 会自动收到最新数据并触发 UI 更新——这是 Drift 区别于普通 SQLite 封装库（如 sqflite）的核心亮点。

## 类图与核心组件

```dart
// 核心类关系示意

// 1. 表定义
class TodoItems extends Table {
  late final id = integer().autoIncrement()();
  late final title = text().nullable()();
  late final createdAt = dateTime().withDefault(currentDateAndTime)();
}

// 2. 数据库主类（需注解 + 代码生成）
@DriftDatabase(tables: [TodoItems], daos: [TodosDao])
class AppDatabase extends _$AppDatabase {
  AppDatabase() : super(_openConnection());
  @override int get schemaVersion => 1;
}

// 3. DAO（数据访问对象）- 模块化查询逻辑
@DriftAccessor(tables: [TodoItems])
class TodosDao extends DatabaseAccessor<AppDatabase> with _$TodosDaoMixin {
  TodosDao(super.attachedDatabase);
  
  Stream<List<TodoItem>> watchTodos() => select(todoItems).watch();
}
```

### 核心设计模式

| 设计模式                       | 在 Drift 中的体现                                               |
| ------------------------------ | --------------------------------------------------------------- |
| **代码生成 (Code Generation)** | 核心范式，通过 `build_runner` 生成类型安全的数据库操作代码      |
| **数据访问对象 (DAO)**         | 通过 `@DriftAccessor` 将查询逻辑模块化，与主数据库解耦          |
| **策略模式 (Strategy)**        | `MigrationStrategy` 支持版本升级时的迁移策略定制                |
| **适配器模式 (Adapter)**       | `QueryExecutor` 抽象接口适配不同平台后端（Native/Wasm/Sqflite） |

## 工作流程

### 1. 定义表 → 生成代码 → 使用

```
编写表类 → 运行 build_runner → 生成 .g.dart 文件 → 使用生成的 API 进行 CRUD
```

### 2. 查询执行流程

```
应用调用查询 (DSL/SQL) 
    → Drift 构建 SQL 语句（参数化，防注入）
    → QueryExecutor 执行
    → SQLite 返回结果
    → 自动映射为 Dart 对象
    → 若是 Stream 查询，自动监听数据变化
```

### 3. 事务处理流程

Drift 支持嵌套事务：

```dart
await transaction(() async {
  // 所有操作原子执行，外部 Stream 只在事务完成后收到更新
  await into(categories).insert(category);
  await (update(todoItems)..where(...)).write(update);
});
// 嵌套事务：内层提交后外层可见，内层回滚不影响外层
```

## 常用示例

**定义表 + 自动主键**：
```dart
class Users extends Table {
  late final id = integer().autoIncrement()();
  late final name = text().withLength(min: 1, max: 50)();
  late final email = text().unique()();
}
```

**响应式查询（Stream）**：
```dart
Stream<List<User>> watchActiveUsers() {
  return (select(users)..where((u) => u.isActive.equals(true))).watch();
}
```

**复杂关联查询**：
```dart
// 使用 Drift 的 DSL 构建 JOIN
final query = select(users).join([
  innerJoin(todos, todos.userId.equalsExp(users.id))
]);
```

**验证 SQL 方式**：
```sql
-- 在 tables.drift 文件中
todosInCategory: SELECT * FROM todos WHERE category = ?;
countEntries: SELECT c.description, COUNT(*) FROM categories c LEFT JOIN todos t ON t.category = c.id GROUP BY c.id;
```

## 使用场景

| 场景                   | 适用度 | 说明                                       |
| ---------------------- | ------ | ------------------------------------------ |
| 复杂关系型数据         | ⭐⭐⭐⭐⭐  | SQLite 原生支持，JOIN、事务一应俱全        |
| 需要实时响应 UI 的数据 | ⭐⭐⭐⭐⭐  | Stream API 让 UI 自动同步数据变化          |
| 大型 Flutter 项目      | ⭐⭐⭐⭐⭐  | 类型安全 + 模块化 DAO，团队协作友好        |
| 简单 Key-Value 存储    | ⭐⭐     | 杀鸡用牛刀，推荐 SharedPreferences 或 Hive |
| 需要云端同步           | ⭐⭐     | Drift 本身不支持同步，需额外实现           |

## 优缺点

### 优点

- **编译时类型安全**：字段名拼写错误在编译阶段即可发现
- **响应式数据流**：通过 Stream 实现数据驱动 UI，减少手动刷新代码
- **灵活的查询方式**：支持 Dart DSL 和原生 SQL 两种方式
- **支持嵌套事务**：复杂业务逻辑下原子性有保障
- **全平台支持**：移动端、桌面端、Web 使用同一套代码
- **活跃维护**：社区活跃，持续更新

### 缺点

- **学习曲线较陡**：需要理解代码生成、注解、Stream 等概念
- **编译时间增加**：`build_runner` 会延长构建时间
- **包体积增加**：生成的代码会增加应用大小
- **不内置加密**：需额外集成 `SQLite3MultipleCiphers` 实现加密
- **无数据同步**：云端同步需自行实现

## 常见坑与避坑指南

| 坑点                      | 说明                                                   | 避坑建议                                                       |
| ------------------------- | ------------------------------------------------------ | -------------------------------------------------------------- |
| **忘记运行 build_runner** | 修改表结构后未重新生成代码，运行时找不到方法           | 每次修改表/DAO 后执行 `dart run build_runner build` 或 `watch` |
| **事务中未 await**        | 事务内异步操作未 await，事务提前关闭导致数据丢失或崩溃 | **务必**对事务内每个数据库操作使用 `await`                     |
| **Stream 在事务内监听**   | 在事务内创建的 Stream 会随事务关闭而关闭               | 在事务外创建 Stream，事务内的变更会在提交后统一推送更新        |
| **迁移策略缺失**          | 数据库版本升级后未定义迁移，导致应用崩溃               | 使用 `MigrationStrategy` 为每个版本定义迁移逻辑                |
| **主键冲突**              | 使用 `autoIncrement()` 时手动插入 id 值导致冲突        | 让数据库自动生成 id，或使用 `id` 的唯一约束                    |
| **非空字段无默认值**      | 添加新列时未设置默认值，旧数据插入失败                 | 使用 `withDefault()` 或 `clientDefault()` 设置默认值           |

## 同类型存储框架对比

| 框架          | 数据模型             | 类型安全   | 响应式   | 同步能力   | 维护状态           | 适用场景                          |
| ------------- | -------------------- | ---------- | -------- | ---------- | ------------------ | --------------------------------- |
| **Drift**     | 关系型 (SQLite ORM)  | ✅ 编译时   | ✅ Stream | ❌          | ✅ 活跃             | 复杂关系数据，需要响应式 UI       |
| **Floor**     | 关系型 (SQLite ORM)  | ✅ 编译时   | ❌        | ❌          | ⚠️ 较慢             | 轻量 SQLite ORM 需求              |
| **sqflite**   | 关系型 (SQLite 封装) | ❌ 手写 SQL | ❌        | ❌          | ✅ 活跃             | 熟悉 SQL，不需要 ORM 的场景       |
| **Isar**      | NoSQL                | ✅ 编译时   | ✅ Stream | ❌          | ⚠️ 不再维护         | 对象存储，高性能 NoSQL 需求       |
| **Hive**      | NoSQL                | ❌ 运行时   | ❌        | ❌          | ❌ 已废弃           | 简单 Key-Value（建议迁移至 Isar） |
| **ObjectBox** | NoSQL                | ✅ 编译时   | ✅        | ✅ 内置同步 | ✅ 活跃             | 高性能对象存储 + 多端数据同步     |
| **Realm**     | NoSQL                | ✅          | ✅        | ❌ 已废弃   | ❌ 2025.09 停止支持 | **不建议新项目使用**              |

### 选型建议

- **复杂关系型数据 + 响应式 UI** → **Drift**（首选）
- **简单关系型 + 熟悉 SQL** → **sqflite**
- **高性能对象存储 + 需要云端同步** → **ObjectBox**
- **简单 Key-Value 存储** → SharedPreferences 或考虑 Isar（注意维护状态）
